# legado-H UI 重做方案 V2 ——「三层换肤」体系

- 状态：提案（待评审）
- 日期：2026-10-10
- 基线版本：H.1.16.1
- 前置文档：`docs/ui-rewrite-plan.md`（V1，定位是"统一地基"；V2 定位是"整体换脸"）
- 写法说明：本文面向非程序员读者，先讲清楚"为什么"和"是什么"，再讲"怎么做"。技术名词第一次出现时都会用大白话解释。

---

## 0. 一句话总结

把整个 App 的"长相"拆成**三层可以分别替换的皮肤**：

| 层 | 管什么 | 像什么 |
|---|---|---|
| ① 主题包 | 颜色、字体、图片（纯美术） | 一桶桶颜料 |
| ② 界面包 | 尺寸、位置、透明度、布局（纯结构） | 户型图 |
| ③ 阅读方案 | 读书界面的全部体验参数 | 书房里属于你自己的布置 |

用户可以像换手机壳一样，**单独换其中任何一层**，三层互相不干扰。皮肤是一份普通文件（zip 压缩包），不发新版本 App 也能换、能分享。

---

## 1. 为什么上一轮"看起来只是小修补"

上一轮（V1，P0~P4）做的是**统一地基**：把散落各处的颜色、圆角、间距、按钮收敛成一套公共定义，让 100 多个页面"变整齐"。它从一开始就写明了"不做视觉大改版"——所以用户看到的变化确实小。

打个比方：V1 是把一栋各房间风格混乱的房子，统一刷成了米白色。**墙还是那些墙，门还是那些门**。

V2 要做的是：让这栋房子支持**整体换装修**——换涂料（主题包）、换户型（界面包）、并且每间书房还能单独布置（阅读方案）。V1 打的地基（统一的颜色名字表、组件库）恰好是 V2 的底座，已完成的工时不会浪费。

## 2. 假装从零开始：一个"可换肤"的阅读 App 应该怎么设计

这一节先把现有代码全部忘掉，纯粹从零思考。

### 2.1 第一步：拆解"外观"这个词

一个 App 界面上的任何东西，都可以归入四类：

1. **美术资源**：颜色、字体、背景图、图标风格——"颜料"。
2. **结构**：导航栏在底栏还是侧边、列表是网格还是单列、面板多大、透明度多少——"户型图"。
3. **交互**：点击哪里翻页、菜单怎么弹出——"门往哪边开"。
4. **内容**：书名、章节文字——"住在里面的人"。

可换肤体系的核心决策就是：**①美术 和 ②结构 做成可替换的"包"，③交互跟随结构包走，④内容永远不属于皮肤**。

而读书界面是阅读 App 的灵魂，用户会花 90% 的时间在里面，且每个人的偏好差异极大（有人要大字、有人要仿真翻页、有人要纸张纹理背景）。所以读书界面要**单独拎出来**，做到第三层"阅读方案"，支持一人多套、每本书可以不一样。

### 2.2 向做得好的开源项目偷师

| 项目 | 它是什么 | 我们抄什么 |
|---|---|---|
| **Telegram（开源版 Telegram FOSS）** | 聊天软件，主题生态极其繁荣 | 主题就是**一个普通文件**（文本/zip），发给朋友、点开即用。门槛低到极致，才有社区生态。我们所有皮肤包都用 zip 文件 + 一键导入导出 |
| **Mihon（原 Tachiyomi）** | 最流行的开源漫画阅读器 | ① 内置十几个精选主题（纯净黑、AMOLED 省电黑、动态取色）；② **动态取色**：跟着手机壁纸自动变配色（Material You）；③ 换主题立即生效不重启 |
| **KOReader** | 老牌开源电子书阅读器 | **多套预设（Profile）**：把字号、行距、边距、翻页方式等几十个参数打包成"一套方案"，一键切换；甚至能一键切换夜间模式全部相关项。这就是我们"阅读方案"的样板 |
| **android/nowinandroid** | Google 官方 Compose 示例工程 | **Token（命名规范）的组织方式**：给每个视觉原子起固定名字，主题只负责"给名字填值"。这是三层体系能成立的底层方法 |
| **AnySoftKeyboard** | 开源键盘，皮肤以插件形式安装 | 反面教材参考：它用"安装独立 APK"的方式装皮肤，用户要开权限、容易被吓住。**我们不用插件，直接导入 zip 文件** |

### 2.3 五条设计原则（从零定下的规矩）

1. **皮肤是数据，不是代码**。皮肤包里只有 zip + json 配置 + 图片字体文件，没有任何程序代码。好处：安全（皮肤不能干坏事）、普通用户也能自制、不用发版就能传播。
2. **缺什么补什么**。皮肤文件里没写的项目自动回退到默认值。半成品皮肤、只改了一个颜色的皮肤，都能正常使用。
3. **三层独立**。换主题包不影响布局；换界面包不影响颜色；阅读方案完全独立于前两者（阅读页可以彻底无视全局主题，像 KOReader 一样"关起门来自己美"）。
4. **受控的自由**。界面包**不是**自由拖拽编辑器（那是无底洞），而是"框架给出若干可选档位，皮肤包选档位 + 微调参数"。自由度控制在开发成本可控的范围内。
5. **安全第一**。解压包要防"压缩炸弹"（一个 10MB 文件解出 10GB）、防恶意路径（`../../` 逃出应用目录）、限制文件大小。这套校验框架本项目已经有了（`visual-resource-packages.md` 的安全规范），直接沿用。

## 3. 三层皮肤的详细设计

### 3.1 第一层：主题包（美术资源）

**回答的问题：这个 App 是什么配色、什么字体、什么质感。**

一个主题包 = 一个 zip 文件：

```text
aurora-night.zip
├─ theme.json          ← 唯一的"说明书"
└─ assets/
   ├─ bg.webp          ← 全局背景图（可选）
   ├─ body.ttf         ← 正文字体（可选）
   └─ title.ttf        ← 标题字体（可选）
```

`theme.json` 长这样（示例，真实文件约 60 行）：

```json
{
  "formatVersion": 1,
  "id": "aurora-night",
  "name": "极光夜",
  "author": "zego",
  "colors": {
    "light": {
      "primary": "#5B6ABF", "background": "#F5F6FA",
      "surface": "#FFFFFF", "textPrimary": "#1C1E26"
    },
    "dark": {
      "primary": "#8C9EFF", "background": "#0F1117",
      "surface": "#1A1D26", "textPrimary": "#E4E7EF"
    }
  },
  "fonts": { "body": "assets/body.ttf", "title": "assets/title.ttf" },
  "images": { "background": "assets/bg.webp" },
  "style": { "cornerStyle": "rounded", "iconStrokeWidth": 1.8 }
}
```

要点：

- 颜色按"角色"命名（primary=主色、surface=卡片底色……全 App 约 40 个角色），**不是**按页面命名。角色是固定清单，皮肤只负责填值——这就是"Token"思想（答题卡：题目固定，答案随便填）。
- 一个包内含日/夜两套配色，跟随系统切换。
- 字体、背景图都是可选项，不填就用默认。
- **内置 6 个官方主题**：晴空白（默认）、墨夜黑、纸张米、AMOLED 纯黑（OLED 屏省电）、动态取色（跟手机壁纸走，借鉴 Mihon）、电子墨水（灰阶高对比，给墨水屏设备）。
- 换主题**立即生效**，不用重启 App。

### 3.2 第二层：界面包（结构资源）

**回答的问题：东西摆在哪、多大、多透。**

先说清楚"受控自由"：App 的每个界面先被拆成几个固定的**槽位**（slot，可以理解为"预留的格子"）。以书架页为例：

```text
书架页的槽位：[顶部栏] [书籍列表] [底部导航] [悬浮按钮]
```

界面包**只能**决定：槽位怎么排、用什么尺寸档位、透明度多少。不能凭空创造新槽位。这就是成本可控的关键。

一个界面包 = 一个 zip（也可以先只有 json，不带资源文件）：

```json
{
  "formatVersion": 1,
  "id": "side-immersive",
  "name": "侧滑沉浸",
  "mainScreen": {
    "navPosition": "bottom",          // bottom 底栏 / side 侧滑栏 / top 顶栏
    "density": "comfortable",          // compact 紧凑 / standard 标准 / comfortable 宽裕
    "navVisibility": "scrollHide",     // always 常驻 / scrollHide 滚动时隐藏
    "glassTransparency": 0.65,         // 面板透明度 0~1
    "glassBlur": true                  // 液态玻璃模糊效果开关
  },
  "bookshelf": { "listStyle": "grid", "gridColumns": 3 },
  "readerMenu": { "menuStyle": "sheet" }  // sheet 底部抽屉 / panel 侧面板
}
```

要点：

- **内置 3 个官方界面包**：
  - 经典底栏（默认，最接近现状，最稳）
  - 侧滑沉浸（导航收进侧滑抽屉，主界面全屏，玻璃质感面板——现有液态玻璃能力的正式归宿）
  - 双栏平板（平板/折叠屏上书架左、详情右）
- 透明度/模糊全局可调，这正是"液态玻璃"从硬编码变成人人可调的参数。
- 界面包的每一项参数都要在主要界面（书架/书城/发现/我的/阅读菜单）生效；小众页面只需跟随主题包即可，不强行槽位化（控制成本）。

### 3.3 第三层：阅读方案（核心体验）

**回答的问题：读书的时候，我看到的每一个像素。**

这是三层里自由度最大、也最重要的一层。一个阅读方案把现有阅读配置的几十个参数分成四组：

```json
{
  "formatVersion": 1,
  "id": "commute-large",
  "name": "通勤大字",
  "typography": {
    "fontSize": 26, "lineSpacing": 1.8, "letterSpacing": 0.1,
    "paragraphSpacing": 8, "columns": 1,
    "font": "assets/body.ttf"
  },
  "paging": {
    "mode": "slide",                  // click 点击翻页 / slide 滑动 / scroll 滚动 / none 无
    "animation": "cover",             // cover 覆盖 / slide 平移 / simulation 仿真 / none
    "tapZones": "leftRight"           // 左右分区 / 上中下 / 全屏右翻
  },
  "background": {
    "type": "paper",                  // color 纯色 / paper 纸张纹理 / image 图片 / gradient 渐变
    "color": "#F7F1E3", "textColor": "#3B2F24",
    "image": "assets/paper.jpg"
  },
  "chrome": {
    "headerFooter": true, "menuTransparency": 0.5,
    "showBattery": true, "statusBarMode": "immersive"
  }
}
```

要点（对标 KOReader 的 Profile）：

- **多方案**：内置至少 3 套（白天精细 / 通勤大字 / 夜间护眼），用户可无限新建。
- **每本书可绑定**：漫画书绑定"翻页+全屏无页眉"方案，小说绑定"滚动大字"方案，切书自动跟随。
- **一键切换**：阅读菜单里左右滑就能换方案，夜间一键切全套（配色+亮度+背景全变）。
- **可分享**：方案导出为 zip（含字体/纸张纹理图），发给别人导入即用。
- 朗读配置（语速/音色等）作为第五组"aloud"挂在阅读方案里，随方案整体切换。

### 3.4 三层怎么叠起来不打架

```text
┌─────────────────────────────────────┐
│ 界面包（结构）                       │ ← 决定"骨架"
│  ┌───────────────────────────────┐  │
│  │ 主题包（美术）                  │  │ ← 决定"皮肤颜色字体"
│  │   ┌───────────────────────┐   │  │
│  │   │ 阅读方案（读书界面）     │   │  │ ← 阅读页内部完全自治，
│  │   │ 颜色字体背景全自己定     │   │  │    可无视外两层
│  │   └───────────────────────┘   │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

裁决规则（谁优先听谁的）：

1. 阅读页内：**阅读方案 > 主题包**（阅读方案里写了的，就按阅读方案来）。
2. 阅读页外：主题包管颜色字体，界面包管结构，井水不犯河水。
3. 任何参数没被皮肤指定 → 用内置默认值兜底。

## 4. 技术上怎么实现（大白话版）

这一节解释几个关键名词和做法，不涉及具体代码。

**Compose（写界面的新方式）**：旧方式是"先画好一张静态图纸（XML 布局），再用代码往里填字"。Compose 是"用代码直接描述界面长什么样"——描述里用的数值变了，界面**自动**跟着变。这个特性天生适合换肤：皮肤一换，喂进去的数值全变了，全 App 界面自动刷新。本项目 38 个页面已经在用 Compose，正好。

**Token（给视觉元素起名字）**：全 App 约定一份"名字清单"，比如 `color.primary`（主色）、`font.body`（正文字体）、`size.navHeight`（导航栏高度）。界面代码只写名字，不写具体值。三层皮肤包的本质就是**三份"名字→值"的对照表**。`modules/uikit` 里已经建好 8 组 Token 名字表（AppColor/AppSize/AppRadius/AppAlpha/AppSpacing/AppMotion/AppTypeScale/AppShapes），这部分已经完成。

**CompositionLocal（全城广播）**：一种全局传值机制。皮肤加载后，把新对照表"广播"出去，所有页面立刻拿到新值并自动刷新——这就是"换主题不用重启"的原理。

**zip 安装器**：负责选文件、解压、安全校验、落盘、广播生效。`ThemePackageManager` 已经实现了其中最难的部分（安全解压、zip 炸弹防御、原子安装、云同步、导入导出 67KB 成熟代码），V2 把它扩展成三种包共用的安装器。

**阅读内核**：阅读页的文字排版、分页、翻页动画是自绘的（`PageView`，118KB，性能极好），**不重写**。V2 只是把它读的"配置来源"从散落的偏好设置改为"阅读方案"——内核不动，只换喂给它的菜单。

## 5. 现有代码对号入座（哪些直接用、哪些升级、哪些不动）

按用户要求：先从零设计完，再把家底装进去。家底盘如下。

### 5.1 完全不动的部分（房子的承重墙和水电）

| 资产 | 位置 | 说明 |
|---|---|---|
| 书源/RSS 解析引擎 | `modules/book`、`modules/rhino` | 核心 bug 不碰 |
| 数据库 | `app/data`（Room） | 书架、书源、进度、笔记全在里面 |
| EPUB 直读引擎 | 见 `docs/epub-direct-engine.md` | 已成熟 |
| 朗读 TTS、WebDAV 备份、Web 服务、在线导入 | `app/service`、`app/web`、`modules/web` | 与皮肤无关 |
| 阅读排版内核 | `ui/book/read/page/`（PageView 等） | 冻结，只换配置来源 |

### 5.2 直接复用的部分（V1 地基 = V2 底座）

| 资产 | 位置 | 在 V2 中的角色 |
|---|---|---|
| 颜色角色名 / 字体角色 / 背景场景 | `modules/theme`（ThemeColorName、FontRole、BackgroundScene、ThemeRepository、ThemeApplier） | **主题包的数据层雏形**，直接升级为"从 zip 安装外部主题" |
| 主题包安装器 | `help/config/ThemePackageManager.kt`（zip 导入导出、云同步、内置日夜主题） | 升级为三包通用安装器（解压/校验/落盘/分享逻辑全保留） |
| Token 名字表 | `modules/uikit/token/*` | 主题包和界面包的字段清单就以它为准 |
| 组件库 + 状态契约 | `modules/uikit`（AppButton、StateLayout、AppToast 等） | 界面槽位的"标准建材" |
| 38 个 Compose 页面 + 17 个阅读面板 | `app/ui/**/compose` | 改造为"读皮肤值"的消费者（大部分已通过 Token 间接读，改造量小） |
| 资源包安全规范 | `visual-resource-packages.md` + SafeZip 系列 | 三类包的安全校验直接套用 |
| 朗读配置对象化 | `reader/aloud/ReadAloudConfig` | 作为阅读方案的"aloud 组" |

### 5.3 需要升级改造的部分

| 现状 | 改造方向 |
|---|---|
| 阅读配置 69 字段大杂烩（`ReadBookConfig`） | 拆成阅读方案的四组字段（排版/翻页/背景/chrome），旧数据一次性自动迁移 |
| 主题只有"内置+外置主题包"一种，布局透明度不可换 | 拆成三层包体系 |
| 液态玻璃硬编码、密度不可调 | 变成界面包的两个参数 |
| MainActivity 侧栏域与 Activity 深度耦合（约 400 行） | 界面包要做"侧滑沉浸"布局，前置任务：先把侧栏拆成独立组件（此前评估过风险，V2 给了必须拆的理由，按纯函数小步走） |
| 皮肤管理入口分散（主题一处、阅读配置一处） | 合并为统一的"皮肤中心"页面 |

## 6. 施工路线图（分期，每期独立发版）

按项目版本规则：每期都是新特性，minor +0.1。

| 期 | 内容 | 用户能看到什么 |
|---|---|---|
| **R1 主题包成型** | ① 定 zip 格式；② 内置 6 官方主题；③ 主题中心页（预览小卡片+一键切换）；④ zip 导入导出分享；⑤ 动态取色 | **第一次"整体换脸"**：全局配色/字体/背景图一键切换，秒级生效。这一期做完，"小修补"的观感就结束了 |
| **R2 阅读方案** | ① 阅读方案数据层（四组+aloud）；② 多方案管理+每书绑定；③ 阅读菜单一键切换；④ 方案 zip 导入导出；⑤ 旧阅读配置自动迁移 | 读书界面彻底自治：建"通勤大字/夜间护眼"两套方案一键换，每本书自动跟自己的方案 |
| **R3 界面包** | ① 槽位化改造主要界面（书架/书城/发现/我的/阅读菜单）；② 内置 3 官方界面包；③ 透明度/玻璃/密度参数化（前置：侧栏从 MainActivity 拆出）；④ 平板双栏 | 导航位置可换（底栏↔侧滑）、密度可调、玻璃质感可开关 |
| **R4 皮肤中心** | ① 三层包统一管理页（三个标签页）；② 所见即所得预览；③ 复用云同步基础设施做在线皮肤分享（可选开关） | 一个入口管理所有皮肤；皮肤文件发给朋友直接导入 |
| **R5 收尾** | ① 旧格式兼容与迁移全量验证；② 自制皮肤文档（面向普通用户的教程）；③ 皮肤组合矩阵测试（3 界面包 × 6 主题 × N 阅读方案不冲突） | 生态可自助：社区可以开始做皮肤了 |

顺序的理由：R1 最能快速兑现"完全重绘"的观感；R2 独立性最强不依赖 R1；R3 工程量最大放后面，且它改动结构，等 R1/R2 验证了皮肤机制后再动结构更安全。

## 7. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 三层叠加组合爆炸（3 布局 × 6 主题 × N 方案） | 参数只经 Token 单通道下发（不存在第二处取值路径），组合只是"值不同"，不是"代码路径不同"；R5 做矩阵测试 |
| 图片背景性能 | 沿用现有方案：按实际显示尺寸采样解码，不整图载入 |
| 恶意皮肤包 | 沿用 SafeZip 全套限制（大小上限/路径白名单/扩展名校验/原子安装） |
| 老用户配置丢失 | 三类旧配置（themeConfig.json、ReadBookConfig 4 个 JSON、SP 键）首启一次性自动迁移，迁移前自动备份 |
| 界面包槽位化工作量失控 | 只槽位化 5 个主要界面；次要页面只跟主题包。明确不做自由编辑器 |
| 侧栏拆分风险（MainActivity 耦合） | R3 前置任务，按纯函数小步走，每步可单独回归 |

## 8. 验收标准（不看代码，直接上手就能验）

1. 换主题包：任意页面 3 秒内全局变色/变字体/变背景，**不重启**。
2. 换界面包：底栏消失变成侧滑导航（或反过来），所有功能照常能用。
3. 阅读方案：建两套方案在阅读菜单一键切换；给 A 书绑定方案 1、B 书绑定方案 2，切书自动跟随。
4. 分享：把主题包 zip 发给另一台设备，导入即用；删掉皮肤包自动回默认主题，不崩溃。
5. 半成品皮肤：手工把 theme.json 里的颜色删掉一半，App 正常运行（缺失项回默认）。
6. 老配置升级：老版本升上来，原有主题选择和阅读设置原样保留。

## 9. 名词小词典

| 词 | 大白话 |
|---|---|
| 主题包 | 一份 zip 文件，装着颜色/字体/图片，导入后全 App 换装 |
| 界面包 | 一份 json/zip，声明"导航放哪、多大、多透明" |
| 阅读方案 | 读书界面的一整套参数（字号、行距、背景、翻页方式……），可存多套、可分享 |
| Token | 给视觉元素起的名字（如"主色"），皮肤包只负责给名字填值 |
| 槽位 | 界面上预留的固定格子，界面包决定格子的摆放和大小 |
| zip | 压缩包格式，皮肤包的文件形式 |
| Compose | Android 新的界面写法，数值变界面自动变 |
| 动态取色 | 跟着手机壁纸自动配色（Material You） |
| AMOLED 黑 | 纯黑背景，OLED 屏幕省电 |
| 原子安装 | 先装到临时目录，全部成功才替换正式目录，失败不会弄坏现有皮肤 |
