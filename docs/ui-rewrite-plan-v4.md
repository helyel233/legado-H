## 0. V3 为什么没通过，V4 改了什么

| 问题 | V4 的回答 |
|---|---|
| V3 把 App UI 和读书界面捆在一个方案里，读书界面被排版内核、69 字段配置拖着，战线太长 | **拆成两个独立工程**：本轮只做 App UI；读书界面单独一个后续工程（另立文档），本轮**一行不动** |
| V2/V3 的档位设计"只给预设不给手调"，用户不能自己拧数值 | 主题包和界面包都改为**「包打底 + 手调覆盖」**：换包一键换装，任何单项参数也能手动微调，两种自由都要 |
| 旧设置界面（100 多个入口、Preference 遗留栈）装不下新体系 | 设置界面和设置接口**按新 UI 的需要重写**，不是在旧设置上打补丁 |

## 1. 范围边界：什么是 App UI，什么是读书界面

这是本方案的第一决策，一条线划清楚：

```text
┌─────────────────── 本轮重做（App UI）───────────────────┐
│ 书架 / 书城 / 发现 / 我的 / RSS                          │
│ 书籍详情页 / 搜索 / 书源管理 / 源编辑 / 备份等所有管理页   │
│ 全部对话框、底部弹窗、弹出菜单、提示（Toast/ Snackbar）    │
│ 主界面骨架（导航栏、侧栏、悬浮球）                        │
│ 设置界面（重写，见第 5 章）                              │
└────────────────────────────────────────────────────────┘
┌─────────── 冻结不动（读书界面，后续工程）─────────────────┐
│ 阅读页正文渲染 / 翻页 / 排版（PageView 内核）             │
│ 阅读菜单 / 阅读配置 17 面板 / 朗读界面与配置              │
│ 读书用的一切设置（字号、背景、翻页方式……维持现状）         │
└────────────────────────────────────────────────────────┘
```

**接缝规则**（防止两块互相渗漏）：

1. 阅读页打开后，内部视觉**完全由旧的阅读配置说了算**，主题包不强加于正文区域——现状本来就基本如此，保持。
2. 但阅读页之外的任何 App UI（包括从阅读页弹出的"回到书架"确认框这类**非阅读配置**的弹窗）归新体系管。
3. 设置里"阅读"分区**原样保留入口和旧逻辑**，只是搬进新设置界面的一个独立分区（后续读书工程再改它）。
4. 后续读书界面工程开工时，App UI 的主题包机制已经就位，读书界面可以直接选择"接入主题包"或"继续自治"，不返工。

## 2. 主题包（美术资源）：可替换 + 可手调

### 2.1 包格式：一个种子色起步

主题包仍是 zip（沿用 `ThemePackageManager` 的安全安装骨架）：

```text
hazel.zip
├─ theme.json
└─ assets/ (bg.webp / ui.ttf，可选)
```

```json
{
  "formatVersion": 1,
  "id": "hazel", "name": "榛子棕", "author": "zego",
  "seed": "#8D6E63",
  "darkStrategy": "tonal",
  "fonts": { "ui": "assets/ui.ttf", "title": "assets/title.ttf" },
  "images": { "background": "assets/bg.webp" },
  "override": { "color.primaryDark": "#B39D86" }
}
```

- **seed 种子色**：一个颜色，用 Material 3 官方算法（`material-color-utilities`）自动推导全 App 约 40 个颜色角色，日/夜两套自动生成、对比度自动达标（WCAG AA）。
- **override**：包作者可选的逐项手工覆盖——皮肤作者的逃逸口。
- 内置 6 个官方主题：晴空白（默认）、墨夜黑、AMOLED 纯黑、纸张米、动态取色（种子=壁纸主色）、电子墨水（灰阶）。

### 2.2 手调层：每个值都能拧（本版新增的核心机制）

**「包打底 + 手调覆盖」三明治**：

```text
取值顺序（从低到高，高层赢了就覆盖低层）：
① 内置默认值
② 主题包（种子推导 + 包内 override）
③ 我的本地手调   ← 新增：用户在"外观设置"里拧过的每一个值
```

- 外观设置里每个可调项（主色、某个背景色、正文字体、背景图、圆角基色……）都是一条滑块/取色器/文件选择。
- 拧过的项出现**「已修改」标记**，可单项"还原为包默认值"，或一键清空全部手调回到纯包状态。
- 换主题包时**手调默认保留**（用户偏好不该被换包冲掉）；提供"清空手调"按钮。
- 手调可随主题导出：导出时可选"只导包"或"包+我的手调"，后者发给朋友就是"你调教好的版本"。
- 存储即 delta：手调只记录改过的键，不复制全量——包升级（比如官方优化了推导）后，没手调的项自动受益。

### 2.3 主题包管什么（字段清单摘要）

| 组 | 内容 |
|---|---|
| 颜色 | 种子色推导 40 角色（主色/底色/卡片/文字/分隔线/成功警告错误…），日夜两套 |
| 字体 | uiFont（界面正文）、titleFont（标题），可选 |
| 图片 | 全局背景图（可日/夜各一张），可选 |
| 质感 | cornerStyle（形状基调，供界面包装修用）、图标线宽基准 |

**不管**：任何尺寸、位置、透明度（归界面包）；读书界面任何东西（冻结）。

## 3. 界面包（非美术资源）：可替换 + 可手调

### 3.1 结构模型：槽位 + 参数

App UI 的主要界面拆成固定**槽位**（预留的格子，防止做成无底洞的自由编辑器）：

```text
主界面槽位：[顶部栏] [内容区] [底部导航] [侧滑栏] [悬浮球]
书架槽位：  [顶部栏] [书架工具条] [书籍网格/列表] [分组侧栏]
……（书城/发现/我的/详情 同理，每个界面 3~5 个槽位）
```

界面包 = 一份 json（可打 zip 带预览图）：

```json
{
  "formatVersion": 1,
  "id": "side-immersive", "name": "侧滑沉浸",
  "nav": { "position": "side", "visibility": "scrollHide" },
  "density": { "level": "comfortable" },
  "glass": { "enabled": true, "transparency": 0.35, "blur": 12 },
  "shape": { "level": "rounded", "scale": 1.0 },
  "shelf": { "style": "grid", "columns": 3 },
  "detail": { "coverRatio": "2:3", "actionBar": "bottom" }
}
```

- **档位**（导航位置、密度、形状风格）决定一揽子联动默认值——普通用户拧档位就够。
- **参数**（透明度、模糊半径、栏数、比例、可见性行为）全部是包里声明的具体数值——这就是手调的接口。

内置 3 个界面包：经典底栏（默认）、侧滑沉浸（侧滑+强玻璃）、极简紧凑（紧凑+方形+无玻璃）。

### 3.2 手调层：和主题包同一套机制

```text
取值顺序：① 内置默认 → ② 界面包 → ③ 我的本地手调
```

- 界面设置页里：先选**界面包**（大格局），再对**单项参数**微调（玻璃透明度滑到 0.5、书架改 4 列、底栏改常驻……）。
- 同样有「已修改」标记、单项还原、一键清空手调、随包导出。
- 档位切换时**提示保留还是重置该项手调**（例如从"侧滑"切回"底栏"，侧栏透明度手调对底栏无意义，自动归档不丢失）。

### 3.3 手调与档位的关系（一条铁律）

> 档位是"参数组的推荐组合"，不是和手调对立的另一种东西。选档位=一次性写入一组默认参数；手调=在那之后改其中任意几项。界面上档位在前（好上手），参数在后（进阶），存储上全是同一张参数表。

### 3.4 生效范围

主题包 + 界面包 + 手调，管到：主界面、书架、书城、发现、我的、详情、搜索、管理页、全部弹窗和菜单、设置界面本身。**管不到**：阅读页内部（冻结，见第 1 章接缝规则）。

## 4. 统一的取值机制（一套规则管两层）

三层结构共用一套机制，不搞两套系统：

```text
        ┌────────────────────────────────────┐
        │  手调层（delta，只存改过的键）        │
        ├────────────────────────────────────┤
        │  主题包 + 界面包（zip 安装/切换）     │
        ├────────────────────────────────────┤
        │  内置默认（出厂值）                  │
        └────────────────────────────────────┘
                          ▼
              词表层 Token（V1 已建成的名字表）
              全 App 界面只认名字不认值
                          ▼
              唯一裁决点 Applicator
              按上述顺序取值；改任何一层 → 广播 → 全局即时生效
```

- **词表 Token**：继续用 `modules/uikit` 已建成的 8 组名字表（颜色/尺寸/圆角/透明度/间距/动效/字阶/形状），按需扩充字段。界面代码里禁止出现第二个取值通道（这是旧病根除的保证）。
- **Applicator**：唯一的取值入口，负责回退链和即时生效（Compose 的全局广播机制，换肤不重启）。
- **delta 存储**：手调、书籍级覆盖等所有"局部改动"统一用"只存差异"的存储格式。

## 5. 设置界面与设置接口重写

### 5.1 为什么必须重写

旧设置是"100 多项平铺 + Android 系统老式列表控件（Preference 遗留栈）+ 入口散落在各处"。新体系有包、有档位、有手调标记、有预览，旧设置界面装不下；而且设置本身也是 App UI 的一部分，必须先穿上新皮肤。

### 5.2 新设置的信息架构（按用户意图分区，不按旧代码分区）

```text
设置
├─ 外观                     ← 新体系的主场
│   ├─ 主题（选包 → 颜色/字体/背景图逐项手调）
│   ├─ 界面（选包 → 导航/密度/玻璃/形状逐项手调）
│   └─ 预览（所见即所得的沙盒页面，改任何项立刻看到效果）
├─ 阅读                     ← 入口保留、内部逻辑冻结（后续读书工程再改）
├─ 朗读                     ← 同上，冻结
├─ 备份与恢复                ← 原有功能迁入新界面（导出内容新增：主题/界面包+手调）
├─ 书源 / 内容 / 其它既有功能 ← 原有功能迁入新界面，逻辑不动
└─ 关于
```

### 5.3 新设置界面长什么样（要点）

- 全部 Compose，用新组件库搭建，第一个"吃自己狗粮"的页面。
- 外观页核心交互：**左边调、右边看**——左半是设置项，右半是实时预览卡片（一个迷你书架+一个迷你详情页的样机），拖滑块立即看到全 App 将变成什么样。
- 每个手调项三种状态：包默认（无标记）/ 已修改（带标记+一键还原）/ 跟随档位。
- 搜索：设置项可搜索（"透明度"直接搜到玻璃透明度滑块），老设置做不到。
- 分区折叠 + 常用置顶，不再百项平铺。

### 5.4 新设置接口（写代码用的规则）

- 沿用并扩展已验证的**设置 DSL**（`SettingSpec` 形态，本项目 P3-d 已用它迁完 17 个阅读面板）：一个设置项=一份声明（类型/范围/默认值/归属分区），界面自动渲染，新增设置项零界面代码。
- 每个设置项声明自己的**取值通道**：走 Token（外观类）还是走独立存储（功能类）。外观类一律不直接读写 SP 键——彻底结束"4 层主题持久化并存"的历史。
- 旧 `PreferKey` 散键的归宿：功能类键迁进新 DSL 存储；外观类键被 Token 体系取代；无人认领的键在迁移器里删除（先备份）。

## 7. 路线图（每期独立发版，新特性 minor +0.1）

| 期 | 内容 | 用户看到什么 |
|---|---|---|
| **A1 主题引擎** | 种子色推导（引 `material-color-utilities`）+ 6 官方主题 + 颜色/字体/背景逐项手调 + 手调标记与还原 | 挑一个颜色全 App 秒变装；任何颜色字体背景可单独拧 |
| **A2 界面引擎** | 槽位化 + 3 官方界面包 + 玻璃/密度/形状全参数手调（前置：侧栏拆出 MainActivity） | 导航位置可换、玻璃透明度是滑块、圆角随手调 |
| **A3 设置重写** | 新设置界面（Compose + DSL）+ 左调右看预览 + 设置搜索 + 旧设置迁移器 + 双胞胎页面删除 | 设置焕然一新；老设置原样翻译不丢 |
| **A4 包生态** | 主题/界面包导入导出 + 包内含手调的"调教版"分享 + 云同步接入 | 把调好的整套外观发 zip 给朋友 |
| **A5 收尾** | 迁移矩阵验证（6 主题×3 界面包×N 手调不冲突）+ 自制皮肤教程 | 社区可自助做皮肤 |

顺序理由：A1 见效最快且不碰结构；A2 依赖侧栏拆分（唯一硬前置）；A3 在两层引擎定型后重写设置，避免返工；读书界面工程在 A 系列完成后另立 B 系列方案。

## 8. 验收标准（上手即验）

1. 换主题包：3 秒内全局变色变字体，不重启；深色模式配色自动生成且协调。
2. 主题手调：把"卡片底色"单独改一个颜色 → 全 App 卡片变色、该项出现「已修改」、一键还原；换包后手调保留。
3. 换界面包：底栏消失变侧滑（或反向），全部功能正常；切回时原手调恢复。
4. 界面手调：玻璃透明度、书架列数、底栏隐藏行为各自可拧，各自带「已修改」标记。
5. 设置：新设置里能搜到"透明度"；外观页改任何项，右侧预览立即变；"阅读"分区里旧的字号/背景设置原样能改（冻结验证）。
6. 升级：老版本主题选择、背景图、字体被翻译进新体系；翻译前自动备份；删掉旧 themeConfig.json 后一切正常（证明不依赖旧文件）。
7. 阅读页冻结验证：本轮任何改动后，读书界面的观感与设置行为与升级前逐项一致。
8. 安全：导入删掉一半字段的包正常（缺项回默认）；恶意路径/超大 zip 被拒。

## 9. 名词小词典

| 词 | 大白话 |
|---|---|
| App UI | 读书之外的一切界面：书架、书城、设置、弹窗…… |
| 主题包 | zip 文件，装着颜色/字体/图片等美术资源 |
| 界面包 | json/zip 文件，装着导航位置、密度、透明度等结构参数 |
| 种子色 | 挑一个颜色，整套配色自动算出来（Material 3 算法） |
| 槽位 | 界面上预留的固定格子，界面包决定格子怎么摆 |
| 档位 | 一拧就联动一组参数的预设挡（如"宽裕"密度） |
| 手调（delta） | 用户单独拧过的值，只记录改过的项 |
| 「已修改」标记 | 拧过的设置项上的小标记，可一键还原为包默认 |
| Token | 给视觉元素起的名字（如"主色"），界面只认名字不认值 |
| Applicator | 唯一取值入口：先问手调，再问包，最后问出厂默认 |
| 设置 DSL | 声明式设置写法：写一份"有哪些设置项"的清单，界面自动生成 |
| 冻结 | 本轮完全不动的代码范围（读书界面） |
