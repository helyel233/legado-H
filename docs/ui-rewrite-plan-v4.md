## 0. V3 为什么没通过，V4 改了什么

| 问题 | V4 的回答 |
|---|---|
| V3 把 App UI 和读书界面捆在一个方案里，读书界面被排版内核、69 字段配置拖着，战线太长 | **拆成两个独立工程**：本轮只做 App UI；读书界面单独一个后续工程（另立文档），本轮**一行不动** |
| V2/V3 的档位设计"只给预设不给手调"，用户不能自己拧数值 | 主题包和界面包都改为**「包打底 + 手调覆盖」**：换包一键换装，任何单项参数也能手动微调，两种自由都要 |
| 旧设置界面（100 多个入口、Preference 遗留栈）装不下新体系 | 设置界面和设置接口**按新 UI 的需要重写**，不是在旧设置上打补丁 |

## 1. 范围边界：什么是 App UI，什么是读书界面

这是本方案的第一决策，一条线划清楚：

```text
┌─────────────────── 本轮重做（App UI）───────────────────┐
│ 主界面 6 Tab：主页 / 书架 / 发现 / 订阅 / 统计 / 我的（沿用现有信息架构，│
│ 默认 6 Tab；"精简导航"开关见 5.5 杂项清单）                │
│ 书籍详情页 / 搜索 / 书源管理 / 源编辑 / 备份等所有管理页   │
│ 全部对话框、底部弹窗、弹出菜单、提示（Toast/ Snackbar）    │
│ 主界面骨架（导航栏、侧栏、悬浮球）                        │
│ 设置界面（重写，见第 5 章）                              │
└────────────────────────────────────────────────────────┘
┌─────────── 冻结不动（读书界面，后续工程）─────────────────┐
│ 阅读页正文渲染 / 翻页 / 排版（PageView 内核）             │
│ 阅读菜单 / 阅读配置 17 面板 / 朗读界面与配置              │
│ 读书用的一切设置（字号、背景、翻页方式……维持现状）         │
└────────────────────────────────────────────────────────┘
```

**接缝规则**（防止两块互相渗漏）：

1. 阅读页打开后，内部视觉**完全由旧的阅读配置说了算**，主题包不强加于正文区域——现状本来就基本如此，保持。
2. 但阅读页之外的任何 App UI（包括从阅读页弹出的"回到书架"确认框这类**非阅读配置**的弹窗）归新体系管。
3. 设置里"阅读"分区**原样保留入口和旧逻辑**，只是搬进新设置界面的一个独立分区（后续读书工程再改它）。
4. 后续读书界面工程开工时，App UI 的主题包机制已经就位，读书界面可以直接选择"接入主题包"或"继续自治"，不返工。

## 2. 主题包（美术资源）：可替换 + 可手调

### 2.1 包格式：一个种子色起步

主题包仍是 zip（沿用 `ThemePackageManager` 的安全安装骨架）：

```text
hazel.zip
├─ theme.json
└─ assets/ (bg.webp / ui.ttf，可选)
```

```json
{
  "formatVersion": 1,
  "id": "hazel", "name": "榛子棕", "author": "zego",
  "seed": "#8D6E63",
  "darkStrategy": "tonal",
  "fonts": { "ui": "assets/ui.ttf", "title": "assets/title.ttf" },
  "images": { "background": "assets/bg.webp" },
  "override": { "color.primaryDark": "#B39D86" }
}
```

- **seed 种子色**：一个颜色，用 Material 3 官方算法（`material-color-utilities`）自动推导全 App 约 40 个颜色角色，日/夜两套自动生成、对比度自动达标（WCAG AA）。
- **override**：包作者可选的逐项手工覆盖——皮肤作者的逃逸口。
- 内置 6 个官方主题：晴空白（默认）、墨夜黑、AMOLED 纯黑、纸张米、动态取色（种子=壁纸主色）、电子墨水（灰阶）。

### 2.2 包内调整：另存为自定义包（V4.8 用户裁决）

**交互模型：选中包 → 进入包详情调整 → 另存为自定义包。** 调整不是浮在包上的一层全局 delta，而是生成属于你自己的包——这最贴近"选不同的包、在包内调整"的直觉，也让 A4 的皮肤导出天然可用（自定义包本身就是完整皮肤）。

```text
取值顺序（从低到高，高层赢了就覆盖低层）：
① 内置默认值（出厂值）
② 当前主题包（种子推导 + 包内 override；自定义包 = 基于某包修改的副本）
```

- 包详情里每个可调项（种子色、策略、38 个颜色角色、全套背景图）都是取色器/文件选择。
- 修改任一项即基于当前包生成/更新**自定义包**；自定义包记录 `basedOn`（复制来源），「已修改」标记 = 自定义包相对基包的差异项，可单项还原为基包值或删除自定义包回到基包。
- 换回官方包随时可以；自定义包可随 A4 导出分享。
- 官方包升级（推导优化）自动惠及未改动的项。

### 2.3 主题包管什么（字段清单摘要）

| 组 | 内容 |
|---|---|
| 颜色 | 种子色推导 40 角色（主色/底色/卡片/文字/分隔线/成功警告错误…），日夜两套 |
| 字体 | uiFont（界面正文）、titleFont（标题），可选 |
| 图片 | **全套背景图（V4.8 裁决：3 个旧背景槽全部归包）**：全局背景（日/夜）、详情页背景（日/夜）、面板背景（日/夜），均可选 |

**不管**：任何尺寸、形状、位置、透明度（全部归界面包——包括圆角和图标线宽，见 3.1 的归口说明）；读书界面任何东西（冻结）。

> 归口判据：**换美术包，要不要动几何？** 要动几何的（圆角、线宽、间距）都是结构参数，归界面包；只有"换了不影响任何尺寸"的（颜色、字体、图片）才是美术资源。这样两个包的边界可以用一句话检验，不会再出现两边都能塞的模糊项。

## 3. 界面包（非美术资源）：可替换 + 可手调

### 3.1 结构模型：全局旋钮，不区分页面

**铁律：界面包只有一套全局参数，所有窗口共用，不存在按页面分别设置。**
顶栏、底栏、书架、主页、发现、订阅、统计、详情、搜索、弹窗、菜单……一切 App UI 窗口读的都是**同一组值**。改一次玻璃透明度，全 App 所有面板一起变；改一次密度，所有列表一起变。从机制上杜绝"这个窗口圆角 10dp、那个窗口圆角 16dp、这个弹窗有玻璃那个没有"的碎裂观感——旧版各页面自由发挥导致的 UI 不统一，在结构上不再可能发生。

界面包 = 一份 json（可打 zip 带预览图）：

```json
{
  "formatVersion": 1,
  "id": "side-immersive", "name": "侧滑沉浸",
  "nav": { "position": "side", "visibility": "scrollHide" },
  "density": { "level": "comfortable" },
  "glass": { "enabled": true, "transparency": 0.35, "blur": 12 },
  "shape": { "level": "rounded", "scale": 1.0, "iconStroke": 1.8 }
}
```

- 四个**全局旋钮**：**导航**（主界面骨架放哪：底栏 / **悬浮胶囊**——现版本悬浮底栏风格的正式化归宿 / 侧滑 / 顶栏）、**密度**（间距/行高/图标尺寸联动）、**玻璃**（透明度+模糊+描边三值联动）、**形状**（全部圆角按比例缩放 + 图标线宽基准——原 V4 草案放在主题包里的"质感"归口于此，理由见 2.3 的判据）。
- **档位**（导航位置、密度级、形状级）决定一揽子联动默认值——普通用户拧档位就够。
- **参数**（透明度、模糊半径、形状比例、图标线宽、可见性行为）全部是包里声明的具体数值——这就是手调的接口。
- 界面包里**没有任何按页面分的字段**（没有 shelf、没有 detail、没有"某窗口专属参数"）。像"书架用网格还是列表"这类选择属于**功能偏好**，住在普通设置里、不进皮肤——它决定的是"内容怎么摆"，不是"界面长什么样"，且各窗口的功能偏好互不影响观感统一。

内置 4 个界面包：经典底栏（默认）、**悬浮玻璃**（悬浮胶囊底栏 + 玻璃质感——现版本悬浮底栏设计的正式化归宿）、侧滑沉浸（侧滑+强玻璃）、极简紧凑（紧凑+方形+无玻璃）。

### 3.2 包内调整：与主题包同一模型（V4.8）

界面包同样采用「另存为自定义界面包」：选中包 → 调整旋钮/参数 → 另存。取值顺序简化为两层（出厂默认 → 界面包）。实现于 A2-1。

```text
取值顺序：① 内置默认 → ② 界面包 → ③ 我的本地手调
```

- 界面设置页里：先选**界面包**（大格局），再对**全局单项参数**微调（玻璃透明度滑到 0.5、图标线宽调到 2、底栏改常驻……）——拧的是全局值，全 App 所有窗口一起响应。
- 同样有「已修改」标记、单项还原、一键清空手调、随包导出。
- 档位切换时**提示保留还是重置该项手调**（例如从"侧滑"切回"底栏"，侧栏透明度手调对底栏无意义，自动归档不丢失）。

### 3.3 档位与自定义包的关系（一条铁律）

> 档位是"参数组的推荐组合"，不是和包内调整对立的另一种东西。选档位=一次性写入一组默认参数；包内调整=在那之后改其中任意几项并另存。界面上档位在前（好上手），参数在后（进阶），存储上全是同一张参数表。

### 3.4 生效范围

主题包 + 界面包 + 手调，管到：主界面（主页/书架/发现/订阅/统计/我的 6 Tab，**沿用现有信息架构，默认不增删合并一级入口**；「收敛为 3 Tab」作为可选能力放**杂项设置**——开启后保留 主页/书架/我的，发现/订阅/统计收进"我的"页二级列表）、详情、搜索、管理页、全部弹窗和菜单、设置界面本身。**管不到**：阅读页内部（冻结，见第 1 章接缝规则）。

### 3.5 书架页：布局功能保留 + 视觉现代化改造

书架的布局调整功能（网格/列表切换、列数、分组）**完整保留**，但做两件事：选项升级为"调好的成品样式"，卡片视觉全面翻新。关键原则不变——书架的**布局选择**是功能偏好（住普通设置），书架的**长相**全部来自全局旋钮 + 主题包，换肤时书架跟着全 App 一起变，不搞特殊。

**（a）布局档位：从"散件组合"升级为 4 种成品样式**

旧版是"网格/列表二选 + 列数滑块"，用户要自己试出好看组合。新版提供 5 种一键成品（每种都是官方调好的参数组合，仍可再微调；三列/四列网格为 V4.11 应用户要求拆分的明确档位）：

| 成品样式 | 效果 | 适合 |
|---|---|---|
| **封面墙** | 3 列大封面，书名叠在封面下方细字，沉浸看图 | 追求美观、书不多 |
| **三列网格** | 固定 3 列，书名+进度两行 | 默认推荐（V4.11 拆分自经典网格） |
| **四列网格** | 固定 4 列，书名+进度两行，屏显更多 | 书多、大屏设备 |
| **双列卡片** | 封面+书名+阅读进度+最近阅读时间，信息完整 | 在读的书多 |
| **极简列表** | 一行一本，小缩略图（可关），密度最高 | 书多、重效率 |

切换入口就在书架页（右上菜单，**沿用现有书架页设置入口的方式**），即切即见；布局档位、列数微调、分组方式、继续阅读卡开关等书架设置**全部保留在书架页内，不进外观设置**——外观设置里没有任何书架专属项。

**（b）封面卡片视觉翻新**（全部消费全局值，不新增专属参数）

- **进度显示**：封面底部一条 2dp 细进度条（已读比例），读完变主题主色对勾角标——旧版的百分比文字挪到卡片信息层，封面保持干净。
- **更新角标**：有更新的书在封面右上角一个小圆点角标（主题包强调色），进书即消。
- **选中态**：批量管理时点按出玻璃层 + 勾选圈（消费全局玻璃/形状旋钮）。
- **书名字阶**：统一走词表字阶（uikit 已有 AppTypeScale），不再各页面自定字号。
- **封面加载**：低分辨率封面按显示尺寸采样解码（沿用 ImageLoader 方案），加载中显示主题色占位底 + 书名首字，失败显示统一占位图——杜绝旧的"碎图+错位"观感。

**（c）分组与"继续阅读"**

- 分组展示美化：分组头（分组名+本组数量）走统一卡片样式；侧滑分组栏（若启用侧滑界面包）走全局玻璃参数。
- 顶部新增可选的**「继续阅读」卡**：上次在读的书 + 进度 + 一键直达，默认开启、可在书架设置关闭——这是用户打开 App 的第一高频动作，值得一个一等入口。

**（d）书架专属与全局统一的边界**

书架专属的只有：布局档位选择（4 选 1）、列数微调、继续阅读卡开关、分组方式——全是"内容怎么摆"的功能偏好。圆角、间距、玻璃、颜色、字体、字阶全部来自全局——验收时切换任意界面包/主题包，书架必须和其它页面同步变装。

### 3.6 视觉资产保全（冻结 ≠ 丢弃）

「读书界面冻结」指不动它的代码，**不是丢弃它已有的视觉能力**。以下资产在 A 系列全程保留、照常可用：

| 资产 | 现状位置 | 保全承诺 |
|---|---|---|
| 阅读气泡包（AdvancedTip，含 SVG / Data URL） | `help/config/AdvancedTip*` | 导入/导出/渲染照常；B 系列接入新主题机制 |
| 高级标题包（AdvancedTitle，含 Lottie / 包内字体 / 背景图） | `help/config/AdvancedTitle*` | 同上；`asset://` 资源别名体系沿用 |
| EPUB 阅读页面模板（reader-templates） | 见 `docs/reader-templates.md` | 模板体系照常；B 系列可受种子色联动 |
| 纸张纹理 / 纸质化效果（paperEffect 等） | 阅读配置（冻结区） | 冻结期内一字不动 |
| 朗读面板 / 阅读菜单既有视觉 | `ui/book/read/**` | 冻结区内不动 |

规则：

1. A3 的双胞胎删除、PreferKey 大扫除、A4 的包生态改造，均以上表为**黑名单**——不得删除其资源目录、解析代码与云备份通道。
2. B 系列（读书界面工程）的目标之一，是把这些视觉杂项**接入**新主题机制：气泡/高级标题的颜色可跟种子色联动；资源包格式统一沿用 `visual-resource-packages.md` 的 v2 清单与安全规范，不另起炉灶。
3. 每期冻结回归在"读书界面逐项一致"之外追加一项：气泡与高级标题包的 导入 → 应用 → 导出 往返正常。

### 3.7 主题和界面管理中心 + 多包库（V4.10 终态模型）

两类包**保持分离**（主题包管美术、界面包管结构），入口**归一**为一个管理中心：```text
「我的」页 → UI 设置 → 主题和界面管理中心
                              ├─ 主题选包（包库）
                              │    ├─ 官方主题（晴空白/墨夜黑/AMOLED/纸张米/动态取色/电子墨水）
                              │    └─ 我的主题包 1 / 2 / 3 / 4 / …（新建/导入/克隆/删除，数量不限）
                              │         └─ 包详情：包内换美术资源（种子色/策略/颜色角色/字体/背景图导入）
                              └─ 界面选包（包库）
                                   ├─ 官方组合（日常/玻璃/沉浸/极简）
                                   └─ 我的界面包 1 / 2 / 3 / 4 / …
                                        └─ 包详情：包内换界面组合（导航样式/密度/玻璃/形状）
```

**「UI 设置」归口铁律（V4.10 用户裁定）**：后续任何 Tab 上新增的入口、或任何类型的功能，**只要涉及 UI 变化、名字里带"UI/外观/主题/皮肤"的，一律放进 我的 → UI 设置**，不得散落在其它设置分区。UI 设置内部结构：

```text
UI 设置
├─ 主题和界面管理中心   ← 包体系（上）
├─ 界面杂项            ← 5.5 杂项清单中的 UI 开关（精简导航、欢迎页、沉浸状态栏等）
└─ （后续 UI 类功能随做随收于此）
```

归类判据一句话：**"关掉它，界面会变吗？"** 会变 → UI 设置；不变但影响功能 → 对应功能卡片；只影响读书界面 → 冻结区。

规则：

1. **点包即应用**；进包详情修改保存在**该包自己身上**（官方包受保护，编辑时自动克隆为"我的包"再改——另存模型）。
2. 包库持久化：每个用户包独立存储（id/name/参数/资产引用），可重命名、克隆、删除；A4 起可 zip 导入导出。
3. 主题中心/界面中心（A1/A2-1 的过渡实现）随管理中心上线**合并退役**，入口统一。
4. A1/A2 已实现的单自定义包（id="custom"）在升级时自动转成包库里的"我的主题包 1 / 我的界面包 1"。

## 4. 统一的取值机制（一套规则管两层）

三层结构共用一套机制，不搞两套系统：

```text
        ┌────────────────────────────────────┐
        │  手调层（delta，只存改过的键）        │
        ├────────────────────────────────────┤
        │  主题包 + 界面包（zip 安装/切换）     │
        ├────────────────────────────────────┤
        │  内置默认（出厂值）                  │
        └────────────────────────────────────┘
                          ▼
              词表层 Token（V1 已建成的名字表）
              全 App 界面只认名字不认值
                          ▼
              唯一裁决点 Applicator
              按上述顺序取值；改任何一层 → 广播 → 全局即时生效
```

- **词表 Token**：继续用 `modules/uikit` 已建成的 8 组名字表（颜色/尺寸/圆角/透明度/间距/动效/字阶/形状），按需扩充字段。界面代码里禁止出现第二个取值通道（这是旧病根除的保证）。
- **Applicator**：唯一的取值入口，负责回退链和即时生效（Compose 的全局广播机制，换肤不重启）。
- **delta 存储**：手调、书籍级覆盖等所有"局部改动"统一用"只存差异"的存储格式。

## 5. 设置界面与设置接口重写

### 5.1 为什么必须重写

旧设置是"100 多项平铺 + Android 系统老式列表控件（Preference 遗留栈）+ 入口散落在各处"。新体系有包、有档位、有手调标记、有预览，旧设置界面装不下；而且设置本身也是 App UI 的一部分，必须先穿上新皮肤。

### 5.2 新设置的信息架构（按用户意图分区，不按旧代码分区）

```text
设置（卡片式，非 UI 功能沿用现版本的功能域分类）
├─ UI 设置                    ← V4.10 入口链
│   └─ 主题和界面管理中心     ← 主题选包 / 界面选包（多包库，见 3.7）
├─ 阅读                     ← 入口保留、内部逻辑冻结（后续读书工程再改）
├─ 朗读                     ← 同上，冻结
├─ 书源与内容               ← 书源/RSS/TXT规则/替换净化 + 封面配置、EPUB 引擎等
├─ 行为与提示               ← 通用行为开关（见 5.5 归类表）
├─ 网络与性能               ← 高刷/抗锯齿/线程/Web服务等
├─ 媒体与音频               ← 耳机线控/音频焦点
├─ AI                       ← 独立分区，现状保留
├─ 备份与恢复                ← 原有功能迁入新界面（导出内容新增：主题/界面包+手调）
├─ 隐私与安全               ← 应用锁等
├─ 杂项                      ← 仅 UI 相关的低频开关（见 5.5 收纳清单）
└─ 关于
```

### 5.3 新设置界面长什么样（要点）

- 全部 Compose，用新组件库搭建，第一个"吃自己狗粮"的页面。
- 外观页核心交互：**左边调、右边看**——左半是设置项，右半是实时预览卡片（一个迷你书架+一个迷你详情页的样机），拖滑块立即看到全 App 将变成什么样。
- 每个手调项三种状态：包默认（无标记）/ 已修改（带标记+一键还原）/ 跟随档位。
- 搜索：设置项可搜索（"透明度"直接搜到玻璃透明度滑块），老设置做不到。
- 分区折叠 + 常用置顶，不再百项平铺。

### 5.4 新设置接口（写代码用的规则）

- 沿用并扩展已验证的**设置 DSL**（`SettingSpec` 形态，本项目 P3-d 已用它迁完 17 个阅读面板）：一个设置项=一份声明（类型/范围/默认值/归属分区），界面自动渲染，新增设置项零界面代码。
- 每个设置项声明自己的**取值通道**：走 Token（外观类）还是走独立存储（功能类）。外观类一律不直接读写 SP 键——彻底结束"4 层主题持久化并存"的历史。
- 旧 `PreferKey` 散键的归宿：功能类键迁进新 DSL 存储；外观类键被 Token 体系取代；无人认领的键在迁移器里删除（先备份）。

### 5.5 杂项收纳清单（盘点现有体系，2026-10-10）

**杂项的定义（V4.6 收窄）：只收 UI 相关的低频开关。** 非 UI 的功能设置不塞进杂项，而是沿用现版本的思路——按功能域分类，各给一张独立卡片，用户按"我要干什么"找卡片，而不是在杂物间里翻。

**（a）杂项：UI 相关低频开关**（来源：`pref_config_theme` / `pref_config_welcome` / `pref_config_discovery` / `pref_config_other` 的 UI 项）

| 组 | 收纳项 |
|---|---|
| **主界面与导航** | 精简导航（收敛 3 Tab，新）· 启动页直达 · 默认主页 · 底部栏管理 · 顶栏管理 · 主页/管理页沉浸状态栏 |
| **发现与订阅** | 发现页模式（新旧版）· 发现页布局 |
| **欢迎页** | 欢迎页显示时间 · 自定义欢迎页（日/夜背景图、文字、图标开关） |
| **个性化** | 更换应用图标 · 语言 |
| **交互显示** | 快速滚动条触摸区 |

**（b）非 UI 功能项 → 各自功能卡片**（沿用现版本分类，只换壳不换归类）

| 卡片 | 收纳项 | 现状归属 |
|---|---|---|
| **书源与内容** | 封面配置（仅 WiFi 加载/高质量/阴影/封面规则/封面集）· EPUB 引擎选择 · 预下载 · 图片缓存 · 漫画浏览界面 · 视频设置 · 自动更新 | `pref_config_cover` / `pref_config_other` |
| **行为与提示** | 自动清理过期搜索历史 · 返回时提示加书架 · 长按菜单编辑器 · 文本操作菜单"搜索"项 | `pref_config_other` |
| **网络与性能** | 高刷新率 · 抗锯齿 · 线程数 · 位图缓存 · Web 服务（保活/端口）· User-Agent · 直链上传规则 | `pref_config_other` / DNS 配置 |
| **媒体与音频** | 耳机线控始终可用 · 忽略音频焦点 | `pref_config_other` |
| **隐私与安全** | 应用锁（本地密码） | `pref_config_other` |
| **开发者选项**（默认折叠） | 记录日志 · 堆转储 | `pref_config_other` |
| **AI** | AI 助手全套 | `pref_config_ai`（独立分区，现状保留） |
| **阅读渲染**（冻结区） | 字体抗锯齿等阅读渲染相关 | `pref_config_read` |

**（c）收纳原则一句话**

> 杂项只收"UI 的开关"；非 UI 的功能按现版本的功能域分类进各自卡片；外观类被新体系取代（翻译后淘汰，见第 6 章）；阅读渲染留在冻结区。

**判断口径**：拿不准某项归哪时问一句——"关掉它，界面会变吗？"会变 → 杂项或外观；不变但影响功能行为 → 功能卡片；只影响读书界面 → 冻结区。

**（d）功能保全协作规则（项目纪律）**

新 UI 是"换壳"，不允许静默丢功能。实施期间（A1~A5）任何时刻发现**现版本有、但新 UI 落地后没有入口/接口承载**的功能（设置项、页面、手势、彩蛋皆算），必须登记到下表并**询问用户裁决**——迁入对应卡片、放杂项、或确认废弃——未经用户确认不得删除。已裁决的记录在此留痕：

| # | 功能 | 现状位置 | 处置（裁决后填） |
|---|---|---|---|
| 1 | 背景图 3 槽（主背景/详情页背景/面板背景） | `PreferKey.bgImage` 等 + 旧主题管理页 | **全部进主题包**（V4.8）：spec.images 扩展为全局/详情页/面板 × 日/夜；渲染接线随 A2 背景加载 Job 拆分切换数据源，期间旧入口照常可用 |
| 2 | 主题手调交互（全局 delta 层） | A1 主题中心 | **改为「另存为自定义包」**（V4.8）：取消全局手调层，编辑即生成自定义包（basedOn 记录基包）；A2 首项任务落地 |

## 8. 验收标准（上手即验）

1. 换主题包：3 秒内全局变色变字体，不重启；深色模式配色自动生成且协调。
2. 主题手调：把"卡片底色"单独改一个颜色 → 全 App 卡片变色、该项出现「已修改」、一键还原；换包后手调保留。
3. 换界面包：底栏↔悬浮↔侧滑（或反向）切换，全部功能正常；切回时原手调恢复。
4. 界面手调：玻璃透明度、图标线宽、底栏隐藏行为各自可拧，各自带「已修改」标记，且改一项全 App 所有窗口同步生效。
5. 全局一致性：任意两个窗口的圆角、密度、玻璃参数完全一致——界面上不存在、代码里也没有"某页面单独覆盖"的通路。
6. 书架：四种布局档位在书架页直接切换即生效；在读的书封面有进度条、有更新的书有角标；切任意主题包/界面包，书架与其它页面同步变装（书架无专属视觉参数）。
7. 导航：默认 6 Tab（主页/书架/发现/订阅/统计/我的）；杂项开"精简导航"后收敛为 3 Tab，发现/订阅/统计可从"我的"页进入。
8. 设置：新设置里能搜到"透明度"；外观页改任何项，右侧预览立即变；"阅读"分区里旧的字号/背景设置原样能改（冻结验证）；杂项只含 UI 开关，5.5（b）表中的功能项全部可在各自功能卡片中找到。
9. 升级：老版本主题选择、背景图、字体被翻译进新体系；翻译前自动备份；删掉旧 themeConfig.json 后一切正常（证明不依赖旧文件）。
10. 阅读页冻结验证：本轮任何改动后，读书界面的观感与设置行为与升级前逐项一致。
11. 安全：导入删掉一半字段的包正常（缺项回默认）；恶意路径/超大 zip 被拒。
12. 视觉杂项保全：气泡、高级标题、EPUB 模板在升级前后导入/导出/渲染照常（纳入每期回归）。

## 9. 名词小词典

| 词 | 大白话 |
|---|---|
| App UI | 读书之外的一切界面：主页、书架、发现、订阅、统计、我的、设置、弹窗…… |
| 主题包 | zip 文件，装着颜色/字体/图片等美术资源 |
| 界面包 | json/zip 文件，装着导航位置、密度、透明度等结构参数 |
| 种子色 | 挑一个颜色，整套配色自动算出来（Material 3 算法） |
| 全局旋钮 | 界面包的四个全局开关（导航/密度/玻璃/形状），全 App 所有窗口共用一组值 |
| 档位 | 一拧就联动一组参数的预设挡（如"宽裕"密度） |
