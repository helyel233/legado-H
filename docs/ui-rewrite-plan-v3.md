## 0. V2 为什么没通过，V3 改了什么

V2 的阅读方案是这么来的：把现有 69 个配置字段重新分成四组。**这不是新规则，是给旧规则换了抽屉柜。**

V3 把顺序彻底反过来：

```text
V2 的顺序：看旧设置有什么 → 打包成方案
V3 的顺序：先定一套全新的、现代化的规则 → 再拿旧设置来"应试"
            （考得上的收编，考不上的淘汰）
```

先说清楚 V3 的"新"新在哪。旧体系（包括 legado 原版和绝大多数老牌阅读器）的配置哲学是：

> **给用户 200 个滑块，让用户自己组装出体验。**

用户被迫当"调参工程师"：想夜间看书？自己去改背景色、文字色、亮度、页眉颜色……改完发现白天模式被弄乱了。

V3 的哲学是：

> **用户只表达 5 个意图，App 负责联动一切。用户想微调时才展开细节，且只记住他动过的那一项。**

这是 Apple Books、微信读书、Mihon 这一代阅读产品的共同做法，也是 Material 3 官方设计规范的方向。

## 1. 从零设计：用户到底想表达什么

忘掉所有现有设置项。一个现代人打开阅读 App，他真正想说的只有 5 句话：

| # | 用户想说的话 | 意图名 |
|---|---|---|
| ① | "我在什么光线下看书" | **场景** Scene |
| ② | "我要多大、多松的字" | **排版** Typography |
| ③ | "我习惯怎么翻页" | **行为** Behavior |
| ④ | "界面多别打扰我" | **沉浸** Immersion |
| ⑤ | "我喜欢什么颜色形状" | **美感** Aesthetic |

V3 的全部配置模型，就是这 5 句话的展开。旧版的 69 字段 + 40 朗读键 + 30 主题键，每一条都必须能翻译成这 5 句话之一才有资格被收编，否则淘汰。

### 1.1 核心洞察：排版跟人走，视觉跟环境走

这是 V3 最重要的设计决策，值得单独一节。

旧版把"背景色（夜）"和"字号"放在同一张配置表里平起平坐——切夜间模式时，字号当然不会变，但用户得手动确认 20 个设置里哪些该跟环境变、哪些不该。

V3 把这 5 个意图切成两组、两条轴：

```text
跟"人"走的（换环境也不变）：        跟"环境"走的（环境一变就变）：
  排版（字号/行距/边距）             场景（纸色/墨色/亮度/对比度）
  行为（翻页方式/动画/点按区）          沉浸（亮度策略也在这里）
  美感（主题包/界面包）
```

于是"夜间模式"在 V3 里不是一个需要手动切换的开关，而是**场景轴上的一次自动滑动**：你设定的字号、行距、翻页习惯原封不动，只有纸和墨换了一套。反过来，"大字模式"也不该把背景搞乱。

## 2. 三层皮肤的新规则

三层换肤的架构保留（主题包/界面包/阅读方案），但**每一层的内部规则全部重新设计**。

### 2.1 主题包：从"填 40 个颜色"到"给一个种子色"

旧思路（也是 V2 的思路）：定义 40 个颜色角色（primary、surface、textPrimary……），皮肤包手工填满。
问题：普通用户根本不知道这 40 个格子是什么，自制皮肤门槛极高。

**新规则：种子色模型**（Material 3 动态色的标准做法）。

一个主题包只需要声明：

```json
{
  "formatVersion": 1,
  "id": "hazel",
  "name": "榛子棕",
  "seed": "#8D6E63",
  "darkStrategy": "tonal",
  "fonts": { "ui": "assets/ui.ttf", "reader": "assets/reader.ttf" },
  "images": { "background": "assets/bg.webp" }
}
```

- **seed**：一个种子色。App 用标准的色调调色板算法（tonal palette）自动生成整套配色——40 个颜色角色全部由这一个颜色推导出来：浅色模式是"淡榛子"，深色模式自动变成"暗夜榛子"，保证对比度达标（无障碍标准 WCAG AA）。
- **darkStrategy**：深色模式的生成策略（tonal 标准 / amoled 纯黑 / muted 低饱和）。
- 想要完全手工控制的高级皮肤作者，仍然可以加 `"override": {...}` 逐项覆盖推导值——**规则是渐进的，不是阉割的**。
- 内置主题 = 6 个种子：晴空白、墨夜黑、AMOLED 纯黑、纸张米、动态取色（种子=手机壁纸主色）、电子墨水（灰阶）。

效果：做一套皮肤的门槛从"理解 40 个颜色角色"降到"挑一个喜欢的颜色"。这是 Telegram 主题生态繁荣不起来的反面教训之一。

### 2.2 界面包：从"槽位参数"到"四个档位旋钮"

界面结构不做自由编辑器（V2 已论证），但 V3 把可调项收敛成 4 个**档位旋钮**（每个旋钮 2~4 档），而不是 V2 那种逐项参数（navPosition/density/glassTransparency… 平铺）：

| 旋钮 | 档位 | 联动了什么 |
|---|---|---|
| **导航** | 底栏 / 侧滑 / 顶栏 | 主界面整体骨架 |
| **密度** | 紧凑 / 标准 / 宽裕 | 全局间距、列表行高、图标尺寸**联动**（不是一个一个调） |
| **玻璃** | 无 / 轻 / 强 | 面板透明度+模糊强度+描边，三值联动 |
| **形状** | 方 / 圆 / 胶囊 | 全部圆角半径按比例缩放（M3 shape scale 思想） |

档位的好处：组合只有 3×3×3×3=81 种（且都被官方测试过），而不是 N 个自由参数的天文数字组合。用户一眼看懂，开发测试可控。

内置 3 个界面包 = 3 组推荐组合：经典底栏（默认）、侧滑沉浸（侧滑+强玻璃+胶囊）、极简专注（侧滑+紧凑+方）。

### 2.3 阅读方案：从"69 字段四分组"到"预设 + 差异"（本方案的重头戏）

V2 在这里摔跤，V3 在这里立新规。

**新规则的三层结构：**

```text
阅读方案 (Profile)
├─ 场景 Scene        日间 / 夜间 / 暗光 / 墨水屏      ← 跟环境走，可自动切换
├─ 风格 Style        排版档位 + 纸墨主题              ← 跟人走
└─ 行为 Behavior     翻页 / 动画 / 点按分区 / 沉浸度   ← 跟人走
```

**规则一：风格是档位，不是滑块群。**

排版暴露给默认界面的是 4 个档位（对应"排版"意图）：

| 档位 | 联动效果 |
|---|---|
| 紧凑 | 字号小、行距窄、段距小、边距窄 |
| 标准 | 出厂值 |
| 宽松 | 字号+2、行距+30%、段距+4 |
| 大字 | 字号+8、行距+50%、边距自适应、自动切换单栏 |

选一个档位 = 旧版手动调 8 个滑块的联动结果。旧版的独立滑块全部还在，只是收进"高级"抽屉（渐进式披露）。

**规则二：方案 = 预设 + 差异（delta），不是全量 69 字段。**

这是现代配置体系（VS Code settings、浏览器 flags、Apple 辅助功能）的通用做法：

```text
方案"通勤大字" = 基础档位[大字]
              + 差异 { 字号: 28, 翻页动画: 平移 }   ← 只有我动过的 2 项
```

- 设置页里逐项显示"已修改"标记，单项一键还原到档位默认值。
- 官方升级档位定义时（比如"大字"档优化了边距），没有手动覆盖该项的用户**自动受益**——旧全量模型做不到这点，用户的 69 字段快照会把改进永远挡在外面。

**规则三：场景自动切换。**

- 跟随系统深色模式：系统切夜间 → 阅读页自动滑到"夜间"场景（纸墨变、排版不动）。
- 可选"暗光自适应"：屏幕亮度低于阈值时自动用"暗光"场景（比夜间更暗一档、对比度略降）。
- 墨水屏设备（或用户声明用墨水屏）直接锁定"墨水屏"场景（灰阶、无动画）。

**规则四：每本书只存差异。**

书籍级配置不再是复制一份完整方案，只存"这本书和它的方案差在哪"（典型如：这本书单独用滚动模式）。方案改了，所有引用它的书自动跟新，未覆盖项不拖后腿。

**规则五：朗读随方案。**

朗读（语速/音色/停顿）作为方案的第四组挂在 Behavior 旁边，属于"跟人走"。切方案 = 换一个人整套听书习惯。

## 3. 新规则下的配置全景（一张图）

```text
                    ┌── 用户只拧这些"旋钮" ──────────────────┐
                    │                                        │
   主题包(美感)      界面包(美感)         阅读方案(排版/行为)    场景(环境)
   种子色+字体      4 个档位旋钮         风格档位+行为+差异     日/夜/暗光/墨水屏
   (zip 可替换)     (zip 可替换)         (zip 可分享)          (自动/手动)
                    │                                        │
                    └──────────────┬─────────────────────────┘
                                   ▼
                        词表层（Token，V1 已建成）
                     所有界面只认名字，不认具体值
                                   ▼
                        唯一裁决点（Applicator）
                     缺项→内置默认兜底，改值→全局即时生效
```

关键承诺：**任何参数只有一条取值通路**（皮肤包 → 词表 → 界面）。旧版"同一个圆角在 dimens.xml、drawable、90 个 kt 文件里各写各的"的病，在新规则下结构性根除。

## 4. 遗产接收表（新规则当考官）

规则立完了，现在旧设置来应试。三档判决：**收编**（有对应语义槽位，直接翻译）、**收敛**（槽位存在但被更高层机制取代，进"高级"抽屉）、**淘汰**（新规则下不再需要的自由度）。

### 4.1 阅读配置 69 字段（`ReadBookConfig.Config`）判决摘录

| 旧字段 | 判决 | 去向 |
|---|---|---|
| textSize / lineSpacingExtra / paragraphSpacing / letterSpacing / 4 组 padding | **收敛** | 风格档位联动值；单项滑块进"高级"抽屉 |
| bgStr / bgStrNight / bgStrEInk / bgType×3 / textBold / paperEffect / paperInkStrength | **收编** | 场景的"纸墨"定义（日/夜/墨水屏三场景——旧版已有三套背景的萌芽，V3 把它扶正为第一性规则） |
| 翻页方式 / 动画 / 点击区域 | **收编** | 行为组 |
| titleMode / titleSize / titleTop/BottomSpacing | **收敛** | 沉浸度档位的联动值（沉浸：纯净→页眉页脚→全显） |
| tipHeader/ Footer × 6 槽位 + 6 个 Template 字符串 | **收敛** | 页眉页脚归并为 3 个开关（时间/电量/进度/章节标题自由组合），自定义模板进高级抽屉，不再占一级界面 |
| headerPadding×4 / footerPadding×4 / showHeaderLine / showFooterLine / tipColor / tipDividerColor | **淘汰** | 由沉浸档位+主题词表推导，不再单独暴露（旧值迁移时折算进档位） |
| textFont | **收编** | 主题包 fonts.reader + 方案级覆盖 |
| paragraphIndent / underlineMode / underlineStrokeWidth / underlineDashLength | **收敛** | 高级抽屉 |
| readerTemplateId（EPUB 模板） | **收编** | 方案的"行为"组，每书可覆盖 |
| headerMode / footerMode | **收敛** | 沉浸档位联动 |

### 4.2 其余遗产判决摘录

| 旧资产 | 判决 | 去向 |
|---|---|---|
| 朗读 40+ PreferKey | **收敛** | 方案 Behavior 的 aloud 组 |
| themeConfig.json 31 字段 + app_themes.xml | **淘汰/收编** | 颜色类字段被种子色模型取代；非颜色字段（圆角比例等）映射到界面包装入"形状"旋钮 |
| 3 个背景槽（backgroundImgPath 等） | **收编** | 主题包 images，按场景可分图 |
| 3 套字体入口 | **收编** | 统一为词表的 uiFont/readerFont/titleFont 三角色 |
| uiCornerScale / liquid glass 硬编码 | **收编** | 界面包"形状""玻璃"旋钮 |
| 夜间模式开关、EInk 开关、亮度 | **收编** | 场景轴（自动切换替代手动开关） |
| 双胞胎页面（BookInfo 两套、书架三套） | **淘汰** | 新规则只认一个实现，另一套物理删除 |
| 阅读内核 PageView / 排版引擎 | **豁免** | 不参试。它只是"执行规则的机器"，新规则通过既有 Config 喂给它 |

### 4.3 接收的执行方式：一次性"翻译器"

升级时跑一个迁移器：旧 69 字段 + SP 键 → 按上表翻译成新结构。**判不进新规则的字段直接丢弃，不做"兼容 graveyard"**（这是旧版配置膨胀 4 层并存的根源）。翻译前自动备份旧 JSON，用户可回退版本。

## 5. 技术实现要点（大白话）

- **词表（Token）**：V1 已建成 `modules/uikit` 的 8 组名字表，继续用，只按新规则扩充字段。
- **种子色推导**：用 Material 3 的 tonal palette 算法（Google 官方开源库 `material-color-utilities` 可直接引入），种子色 → 40 角色全推导，深浅两套自动生成，对比度自动达标。
- **差异（delta）模型**：方案存储 = `风格档位 + {改过的键: 值}`，读取时"档位默认值 → 叠加差异"两步合成。
- **唯一裁决点**：所有界面向同一个 Applicator 要值，它负责"皮肤包 → 词表 → 默认值"的回退链，保证换肤秒生效、半成品皮肤不崩溃。
- **自绘阅读内核不动**：新规则最终仍编译成内核认识的参数喂给它，内核零改动。
- **三层包安装器**：沿用 `ThemePackageManager` 的安全解压/原子安装/云同步骨架，扩展支持三种包。

## 6. 路线图（每期独立发版，均为新特性 minor +0.1）

| 期 | 内容 | 用户看到什么 |
|---|---|---|
| **N1 新主题引擎** | 种子色推导 + 内置 6 主题 + 主题中心 + zip 导入导出 | 挑一个颜色，全 App 秒变装；夜间配色自动生成且达标 |
| **N2 阅读方案（新规则）** | 场景/风格/行为三层 + delta 存储 + 场景自动切换 + 每书差异 + 旧配置一次性翻译 | "夜间模式"变自动的；风格一个档位顶过去 8 个滑块；改过的设置带"已修改"标记可单项还原 |
| **N3 界面档位化** | 4 旋钮 + 内置 3 界面包 + 主要页面槽位化（前置：侧栏从 MainActivity 拆出） | 导航位置/密度/玻璃/圆角四个旋钮随手拧 |
| **N4 皮肤中心** | 三层包统一管理 + 预览 + 分享 | 一个入口管所有皮肤，发 zip 给朋友即用 |
| **N5 生态收尾** | 翻译器全量验证 + 自制皮肤教程 + 81 组界面档位×6 主题×多场景矩阵测试 | 社区可自助做皮肤 |

顺序理由：N1 立刻兑现"完全重绘"观感且不碰阅读；N2 是新规则的核心战场，独立于 N1 可并行准备；N3 动结构，放在皮肤机制验证之后最稳。

## 7. 验收标准（上手即验）

1. 皮肤中心选种子色"深红"，3 秒内全 App 换装，深色模式下自动是另一套协调的深红，不重启。
2. 系统切夜间模式：阅读页纸墨自动变夜间、字号行距翻页方式原样不动。
3. 风格选"大字"，页眉页脚边距自动联动合理；进高级抽屉把字号单独改到 28，该项出现"已修改"标记，一键还原。
4. A 书用方案 1，单独把它改成滚动模式——只有这本书是滚动；回到方案 1 修改行距，A 书的行距跟着变（未覆盖项跟新）。
5. 导入删掉一半字段的皮肤 zip，App 正常（缺项回默认）；导入恶意路径 zip 被拒。
6. 老版本升级：原阅读设置被翻译成新方案，观感不回退；翻译前自动备份。
7. 手工删掉旧 `ReadBookConfig` 的 JSON，App 依然按新方案正常读书（证明新规则不依赖旧文件）。

## 8. 名词小词典

| 词 | 大白话 |
|---|---|
| 意图 | 用户真正想说的话（"我要大字"），App 把它翻译成一堆参数 |
| 种子色 | 挑一个颜色，整套配色自动算出来 |
| 色调调色板 | 那个"从一个颜色算出一家人颜色"的算法，Material 3 标准 |
| 档位 | 一拧就联动多个参数的预设挡位（像空调的风量挡） |
| 差异（delta） | 只记录"我改过什么"，没改过的跟预设走 |
| 场景 | 环境预设：日间/夜间/暗光/墨水屏 |
| 渐进式披露 | 常用的露在外面，细节收进"高级"抽屉 |
| WCAG AA | 无障碍对比度标准，保证浅底深字看得清 |
| 翻译器 | 升级时把旧设置一次性换算成新规则的一次性程序 |
| Applicator | 唯一的取值裁决点：先问皮肤包，没有就问默认值 |
