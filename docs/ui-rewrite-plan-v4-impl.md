### 0.2 版本与发版

- 每期一次发版，均为新特性：minor +0.1（如 H.1.16.1 → H.1.17.0），versionCode = 29860000 + git rev-list count。
- 发版流程照 `docs/release-process.md`：CHANGELOG + updateLog 先提交再 tag；`build-signed.sh` 产物重命名为 `legado_app_H.<ver>_<code>_LegadoH_arm64.apk` 再跑 `create-release.sh`；release/debug 严禁并行，debug 前 `./gradlew --stop`。
- 期间产生的纯 bug 修复按 patch 规则走，不占期号。

### 0.3 工程纪律

- **单一取值通道**：任何新 UI 取值只许走 Token/Applicator，新增一个直接读 SP 颜色键的 kt 文件即视为违规（grep 验收：`uikit/` 与新写 Compose 页面中不得出现 `Color(0xFF` / `Color.parseColor` / `getPrefString(".*[Cc]olor")`）。
- **小步提交**：每任务一个可编译提交，提交信息带任务号（如 `A1-3 seed palette engine`）。
- **旧代码不删先禁**：淘汰类（如双胞胎页面）先从导航摘除入口，确认一版无回归后再物理删除（A3 集中删）。
- **功能保全询问制**：实施中发现"现版本有、新 UI 落地后没有接口承载"的功能（设置项/页面/手势/彩蛋），必须登记进方案 5.5（d）功能裁决表并**询问用户**，确认归属（功能卡片/杂项/废弃）后方可动它；未经确认一律保留原入口。
- **每期收尾必跑**：`./gradlew :app:assembleDebug` + 阅读页冻结回归（打开一本本地书逐项对照：字号/背景/翻页/菜单/朗读）+ 气泡/高级标题包导入→应用→导出往返 + 本期验收清单。

## A1 主题引擎（种子色 + 手调）

**一句话**：挑一个颜色，全 App 秒变装；每个颜色/字体/背景可单独拧，拧过的带「已修改」标记。

**用户故事**
1. 我在"设置→外观→主题"里选了内置主题"墨夜黑"，3 秒内全 App 变装，不重启。
2. 我把种子色调成深红，深色模式自动生成一套协调的深红，对比度达标。
3. 我单独把"卡片底色"改成另一个颜色，该项出现「已修改」，一键还原。

### 任务分解

**A1-1 引入种子色算法库**
- 依赖二选一（实施时按体积与维护度定）：Google 官方 `material-color-utilities`（Java，经 JitPack `com.github.material-foundation`）或其 Compose 封装 MaterialKolor（`com.materialkolor`）。写入 `gradle/libs.versions.toml`（现有 composeBom 2025.10.00 / material3 1.4.0 兼容）。
- 产出：`modules/theme/.../palette/SeedPalette.kt`——输入 `seed: Int + darkStrategy(tonal|amoled|muted)`，输出 40 个角色的日/夜两套颜色值（角色清单以 `ThemeColorName` 现有枚举为准对齐，缺的补枚举）。
- 自检：纯函数、可单测（给定种子断言输出对比度 ≥ WCAG AA）。

**A1-2 主题包新格式 v1（数据层）**
- `modules/theme/.../package/ThemePackageSpec.kt`：`formatVersion/id/name/author/seed/darkStrategy/fonts/images/override` 的数据类 + Gson 解析 + **容错**（未知字段忽略、缺失字段为 null——半成品包必须能加载）。
- 与现有 `themeConfig.json` 31 字段的关系：新格式是入口，`ThemeConfig.Config` 在 A1 仅作翻译目标保留（老主题包导入时翻译成新格式，经 PkgMgr `importPackageDetailed` 改造）。
- 目录：外置包落 `externalFiles/themePackages/`（沿用现有布局），内置 6 主题随 app assets 发布。

**A1-3 内置 6 主题**
- 晴空白（默认种子 #5B6ABF 系）、墨夜黑、AMOLED 纯黑（darkStrategy=amoled）、纸张米、动态取色（种子=壁纸主色，接 `dynamicColor` API，Android 12+ 生效、以下回退晴空白）、电子墨水（灰阶种子）。
- 每个主题一份 `assets/themes/<id>/theme.json`（纯数据，无一行 kt）。

**A1-4 Applicator：三明治取值 + 即时生效**
- `modules/uikit/.../theme/` 新增 `Applicator`：取值顺序 内置默认 → 包（seed 推导 + override）→ 手调 delta；经 Compose 全局广播（CompositionLocal）下发，替换/扩展现有 `AppColorProvider`/`AppTheme` 的职责（保持对外 API 兼容，38 个已 Compose 化页面零改动或极小改动）。
- 存储三张表：`activeThemeId`（当前包）、`tweaks.json`（手调 delta，只存改过的键）、内置默认常量表。禁止任何外观值再写 SP 键（`ThemeApplier.write*` 仅保留给迁移器调用，A3 后退役）。

**A1-5 外观设置页（主题分区，最小可用版）**
- 全 Compose，用 DSL 声明设置项；含：主题包选择列表（名称+作者+小色卡预览）、种子色取色器、darkStrategy 选择、字体选择（uiFont/titleFont 复用现有字体文件选择器）、背景图选择、手调区（列出 40 角色的取色器，懒加载分组）。
- 每个手调项三态：包默认（无标记）/ 已修改（标记+单项还原）/ 一键清空全部手调。
- 换包时手调默认保留，弹一次性提示说明（"你的手调将保留，可一键清空"）。

**A1-6 旧主题翻译器（第一版）**
- 首启检测旧 `themeConfig.json` / SP 主题键 → 翻译为"内置近似主题 + 手调 delta"（旧自定义色逐项进 override/delta）；翻译前把旧文件整体备份到 `backups/ui-v4/`；翻译只跑一次（标记位）。
- 对照策略：旧"内置日/夜主题"直接映射到新内置主题；旧自定义色找不到语义槽位的，落 override 保色不保名。

**A1-7 收尾**
- grep 验收（见 0.3）、阅读页冻结回归、CHANGELOG、发版 H.1.17.0。

## A2 界面引擎（全局旋钮 + 手调 + 书架改造）

**一句话**：导航位置/密度/玻璃/形状四个全局旋钮接管所有窗口；书架换 4 种成品布局。

**前置硬依赖**：MainActivity 侧栏域拆分（约 400 行、30 个函数与 pagePosition/fragmentMap/导航分发/背景加载 Job 深耦合）。按纯函数小步走：先抽"背景加载 Job"与"导航分发"两个最小闭包，每步独立可回归；**不追求 30KB 目标，只拆到侧栏成为可独立重组的组件**（`SideNavHost`），侧滑/底栏两种骨架都能挂它。

**用户故事**
1. 我在"外观→界面"里把导航从底栏切成侧滑，主界面骨架变了，功能全在。
2. 我把玻璃透明度滑到 0.5，主页、书架、详情、所有弹窗的面板一起变半透明。
3. 我在书架页右上菜单把布局切成"封面墙"，即切即见；在读的书封面底部有进度条。

### 任务分解

**A2-1 界面包格式 + Applicator 扩展**
- `uikit` 新增 `LayoutPackageSpec`（nav/density/glass/shape 四组，仅全局字段），取值并入 Applicator 取值链。
- **包内调整模型（V4.8 用户再次确认，与主题包一致）**：可选不同的包 → 包内调整参数 → **另存为自定义界面包**（basedOn 记录基包）。不做全局手调 delta 层（原 `layoutTweaks.json` 方案作废）；「已修改」标记 = 自定义界面包相对基包的差异项，可单项还原或删除自定义包回基包。
- 内置 4 包：经典底栏（默认）、悬浮玻璃（悬浮胶囊底栏+玻璃——现版本悬浮底栏设计的正式化归宿）、侧滑沉浸、极简紧凑。纯 json 资产。
- **铁律检查点**：spec 中出现任何按页面字段即打回（方案验收第 5 条的机制保证）。

**A2-2 侧栏拆分（前置）**
- 见上。产出 `SideNavHost` 组件 + MainActivity 瘦身（预期 92KB → 60KB 级，不设死指标）。

**A2-3 导航旋钮**
- 主界面骨架四态：底栏 / **悬浮胶囊**（玻璃 dock 悬浮于内容之上，现版本悬浮底栏风格的正式化）/ 侧滑（侧滑态吃 SideNavHost）/ 顶栏；`navVisibility`（常驻/滚动隐藏）作用于当前骨架。**Tab 清单默认沿用现有 6 Tab：主页/书架/发现/订阅/统计/我的；杂项设置提供"精简导航"开关（收敛 3 Tab：主页/书架/我的，发现/订阅/统计收进"我的"二级列表，A3 落地），属功能偏好不进皮肤体系。**
- 旧 `MainBottomNavConfig`（AppearanceKitManager 中）翻译进新链路。

**A2-4 密度/玻璃/形状旋钮接线**
- 密度：AppSpacing/AppSize/AppTypeScale 三组 Token 乘密度系数联动（紧凑 0.85 / 标准 1.0 / 宽裕 1.15）；列表行高、图标尺寸、区块间距全部随之。
- 玻璃：`StableLiquidGlassView` 与 Compose 玻璃组件的参数统一改为读旋钮（透明度 0~1、模糊 0~24dp、描边开关三值联动）；现有 `layoutAlpha/dialogAlpha/cornerScale` SP 键由翻译器折算进包/手调。
- 形状：AppRadius/AppShapes 全部圆角 × scale（0=方 / 0.5=圆 / 1.0=胶囊基准），iconStroke 为图标线宽基准（158 个自绘 vector 不改文件，显示层按基准缩放 stroke）。
- **旧页面接线策略**：38 个 Compose Screen 多已走 Token，属"顺带生效"；仍写死 `.dp` 的 XML 页面（详情页、编辑页等）本期内只接顶/底导航和弹窗层，全面改造留待其自身 Compose 化时顺带完成（不为本期返工老 XML）。

**A2-5 书架改造（方案 3.5 节全文落地）**
- 4 种布局档位（封面墙/经典网格/双列卡片/极简列表）：新建 `ShelfLayoutMode` 偏好；**布局/列数/分组/继续阅读卡设置全部保留在书架页内**（沿用现有书架页设置入口方式），即切即见，外观设置无书架专属项。
- 卡片组件 `BookCoverCard`：底部 2dp 进度条（读完主色对勾角标）、更新圆点角标（进书即消）、玻璃选中态、占位底+书名首字（封面失败）、按显示尺寸采样解码（复用 ImageLoader + AndroidView 包装模板）。
- 「继续阅读」卡：上次 `durChapter` 非零的最近在读书，一键直达（默认开、书架设置可关）。
- 分组头统一卡片样式；书架一切视觉值走 Token，**书架文件中不得新增颜色/圆角常量**（grep 验收）。

**A2-6 收尾**
- 冻结回归 + 验收 + 发版 H.1.18.0。

**一句话**：主题包/界面包 zip 可导入导出，可带手调导出成"调教版"发给朋友。

### 任务分解

**A4-1 双包安装器**

- 导入 `-tuned` 包 = 装包 + 预填手调（手调标记照常出现，可还原到包默认）。

**A4-4 云同步接入（可选开关）**
- 复用 PkgMgr 现有 upload/download 容器逻辑（同 ThemeConfig 云通道），默认关。
