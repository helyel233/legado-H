## 0. 为什么推翻 V4：你感觉对了

上一版（V4）走的是**绞杀式**：旧身体不动，新体系一层层长上去，最后一期才拆旧的。代码现状可以证明这一点：

| 现象 | 证据（2026-10-11 代码现状） |
|---|---|
| 旧设置栈一个没删 | `res/xml/pref_config_*.xml` 12 个全在 |
| 旧取值通道还活着 | `AppColorProvider` 仍被 `UiKitBridge` / `AppColorScheme` 引用 |
| 主界面没换骨架 | `MainActivity.kt` 拆了两轮，**仍 2141 行**，一人身兼宿主 / 导航 / 玻璃 / 侧栏 / 指示器 / 启动编排 / 剪贴板导入 |
| 页面各自为政 | 231 个 XML 布局、104 个 Activity，只有 24 个挂了 Compose |
| 接缝 bug 密集 | 最近 3 个提交全是刷新 / 空安全 / 状态同步问题 |

结果就是：**新能力长在旧结构上，形状被旧结构决定**。某些页面换肤跟上了、某些没有——不是新体系没做对，是旧结构还在自己画自己。

### V5 的做法：先造身体，再搬内脏

```text
V4（废弃）                          V5（本方案）
─────────────────────           ─────────────────────
新引擎 → 往旧页面逐个接线          ① 定骨架契约（Host/Content 怎么分工）
       → 最后才拆旧的              ② 造空壳 App：只有骨架 + 占位页，能跑能换肤
                                  ③ 建组件库（现代化零件）
                                  ④ 接包体系（主题包 / 界面包）
                                  ⑤ 业务一页一页搬进去，搬一个旧的退一个
                                  ⑥ 收尾：新设置 + 旧设置导入 + 教程
```

**关键差别**：V4 里"页面愿不愿意变好看"取决于它自己；V5 里**页面没有画外框的接口**——外框（顶栏、底栏、侧栏、背景、圆角、玻璃、动效）一律由宿主渲染，页面想自作主张也做不到。

### 本轮五条前提（用户裁定）

| # | 前提 | 含义 |
|---|---|---|
| 1 | **代码可以完全重写** | 不背"兼容旧代码"的包袱，需要重写就重写 |
| 2 | **视觉效果更现代化是核心目标** | 不追求"和原版一样"，追求"比原版好一个时代" |
| 3 | **双包体系不变** | 主题包管美术素材，界面包管非美术参数，都是多包库 |
| 4 | **读书页不动，留接口** | 阅读页本轮冻结；但预留接入点，以后能一键接进来 |
| 5 | **改版期间不做旧存档兼容** | 不写迁移器、不做双写；最后一期做一个"从旧版本导入设置"的一次性转换器 |

## 1. 目标：什么样的观感叫「现代化」

这一章是本文档最重要的部分。先说清楚要什么，后面所有规则都从这里推出来。

### 1.1 现在的观感问题在哪（对照清单）

| 问题 | 具体表现 |
|---|---|
| 圆角各写各的 | 这个窗口 10dp、那个 16dp、弹窗又是另一套，没有统一形状语言 |
| 玻璃只是"半透明" | 单纯调 alpha，没有模糊层次、没有高光、没有噪声，看着像蒙了层塑料 |
| 动效几乎为零 | 页面跳转是硬切，图标选中是换张图，列表滚动顶栏不响应 |
| 密度偏挤 | 边距小、行高紧、信息堆在一起，老 Android App 的观感 |
| 状态处理原始 | 加载是转圈、空态是一行字、错误是个 Toast |
| 层次靠阴影 | 深浅关系全靠 elevation 阴影，没有材质区分 |
| 顶栏底栏各页面自绘 | 有的页面有、有的没有、有的高度不一样 |

### 1.2 现代化目标（10 条，验收逐条过）

| # | 目标 | 你会看到什么 |
|---|---|---|
| 1 | **统一形状语言** | 全 App 所有容器（卡片/面板/弹窗/侧栏/底栏/按钮/输入框）共用一套形状族，不存在"某个窗口圆角不一样" |
| 2 | **真玻璃材质** | 半透明面板有背景模糊 + 顶部高光描边 + 细噪声纹理 + 轻微饱和度提升，像真玻璃而不是塑料片 |
| 3 | **材质分档代替阴影** | 层次关系由"材质强度"表达（平铺 / 嵌入 / 浮起 / 悬浮），不靠一层黑影 |
| 4 | **动效有生命** | 跳转是容器变换（列表项展开成详情页）、图标选中会形变、滚动时顶栏折叠/底栏隐藏、一切过渡走弹性曲线 |
| 5 | **呼吸感** | 8dp 网格，屏幕边距更宽，区块之间有留白，不挤成一团 |
| 6 | **排版有层级** | 标题更大更重、正文更清晰，一眼能分清"这是标题/这是内容/这是辅助信息" |
| 7 | **状态是设计过的** | 加载是骨架屏（shimmer）、空态有插画和行动按钮、错误可一键重试 |
| 8 | **图标统一且会动** | 全 App 线宽一致、可切换描边/填充风格，选中时有形变动画 |
| 9 | **色彩有主张** | 一个种子色推出整套配色，日/夜自动配对，对比度自动达标；强调色敢于用大面积色块 |
| 10 | **主界面骨架可换** | 底栏 / 悬浮胶囊 / 侧栏 / 顶栏四种形态切换，功能一个不少，观感焕然一新 |

### 1.3 一句话总结

> **旧版是"功能堆在一起"，新版是"内容放在一个有设计的容器里"。**
> 用户打开的每一屏，都应该先感受到"这是一个精心设计的界面"，然后才是"这里有哪些功能"。

## 2. 新骨架：Host 与 Content 的契约

这是 V5 的骨架本体。理解了这一章，就理解了整个方案。

### 2.1 一条铁律：页面不画外框

```text
┌──────────────────────────────────────────────┐
│  Host（宿主，全 App 只有一个实现）              │
│  ┌────────────────────────────────────────┐  │
│  │ 背景层 L0                               │  │
│  │ ┌────────────────────────────────────┐ │  │
│  │ │ 容器层 L1：顶栏 / 侧栏 / 底栏        │ │  │
│  │ │ ┌────────────────────────────────┐ │ │  │
│  │ │ │ Content（内容，页面只写这块）    │ │ │  │
│  │ │ │  卡片 / 列表 / 表单 / 详情       │ │ │  │
│  │ │ └────────────────────────────────┘ │ │  │
│  │ └────────────────────────────────────┘ │  │
│  └──────────────────────────────────────────┘  │
│  弹层宿主（弹窗 / 菜单 / Toast / 底部抽屉）      │
└──────────────────────────────────────────────┘
```

**页面（Content）能做的**：提供内容、声明自己需要什么（见 2.4）。
**页面不能做的**：画顶栏、画底栏、定圆角、定背景、定动效、自己写颜色值。

机制保证（不是靠自觉）：Content 的绘制环境里**拿不到**这些参数——宿主给的绘制上下文里没有"自定义外框"的接口，只有"用第几档材质 / 用哪个语义色"的名字表。

### 2.2 三层表面模型（Surface Model）

全 App 任何一屏都拆成三层，这是所有视觉规则的坐标系：

| 层 | 谁 | 管什么 | 举例 |
|---|---|---|---|
| **L0 背景层** | 宿主独占 | 背景图 / 渐变 / 纹理 / 纯色，可模糊、可压暗、可加遮罩 | 书架的背景图、纯色底 |
| **L1 容器层** | 宿主独占 | 顶栏、侧栏、底栏、卡片、面板、弹窗、菜单——统一材质 | 玻璃侧栏、卡片、底部弹窗 |
| **L2 内容层** | 页面负责 | 文字、图标、控件、分隔线、进度条 | 书名、封面、开关、进度条 |

**L1 容器的材质分四档**（代替旧的"阴影 elevation"）：

| 档 | 名字 | 材质 | 用在哪 |
|---|---|---|---|
| **E0** | 平铺 | 无容器，内容直接落在背景上 | 大段文本区、沉浸内容 |
| **E1** | 嵌入 | 比背景略深或略浅，无描边无阴影 | 列表分组底、输入框 |
| **E2** | 浮起 | 玻璃（模糊+透明）+ 细描边 + 极弱阴影 | 卡片、面板、菜单 |
| **E3** | 悬浮 | 强玻璃 + 高光描边 + 明显阴影 + 入场动效 | 弹窗、侧栏、悬浮底栏、抽屉 |

界面包的参数（玻璃开关、模糊强度、描边开关）作用在 **E2/E3** 两档上，E0/E1 不受影响——所以关掉玻璃时界面变成干净的实色卡片，而不是一片糊。

### 2.3 页面注册制（Tab 只有一个真相）

现状问题：Tab 清单在 `MainBottomNavConfig` 有一份，MainActivity 里又手写了 id→Fragment 映射和菜单构建，侧栏还是底栏菜单的镜像——三处真相。

新骨架：**一张注册表，宿主从它构建一切。**

```text
AppDestination（一个页面 = 一条注册）
├─ id / 图标 / 标题
├─ 内容工厂（怎么画出这个页面）
├─ 能否作为 Tab（可导航项）
├─ 顶栏需求（无 / 标题 / 搜索 / 大标题折叠）
└─ 侧栏分组（出现在侧栏的哪一区）

        ▼ 宿主读注册表，自动生成
底栏菜单 / 侧栏菜单 / 顶栏 / 内容路由 / 二级入口
```

好处：
- 加一个 Tab、换 Tab 顺序、精简成 3 Tab、Tab 变成侧栏项——**改注册表一行，四处自动同步**。
- 侧栏不再是底栏的镜像，而是注册表按分组的另一种排布。

### 2.4 页面怎么声明自己（契约示例）

页面只写三件事，其它全是宿主的事：

```text
页面声明：
  标题 = "书架"
  顶栏 = 大标题折叠（滚上去时收成小标题）
  右上角操作 = [搜索, 布局切换]
  内容 = 「书架内容」（自己的业务逻辑）
  滚动行为 = 向下滚时底栏自动隐藏
  需要进入动画 = 无（Tab 切换不做容器变换）
```

宿主收到这份声明后，自己决定：顶栏多高、什么材质、标题什么字号、操作按钮什么形状、滚动时怎么折叠、底栏怎么隐藏。**页面完全不知道这些。**

### 2.5 迁移期：未搬迁的旧页面怎么办

现实约束：104 个 Activity、231 个 XML，不可能一次搬完。方案给出**降级容器**：

| 页面级别 | 处理方式 |
|---|---|
| **一级页面**（6 Tab + 设置 + 书籍详情 + 搜索 + 主要管理页） | 完整搬进新骨架，写 Content 实现 |
| **二级/三级页面**（大量编辑页、规则页、管理页） | 挂 `LegacyScreenHost`：宿主自动给它套上新顶栏、新背景、新材质、新动效；页面内部 XML 原样运行 |
| **读书页及相关** | 冻结，走独立通道（见第 5 章） |

`LegacyScreenHost` 的意义：**不用等搬完，第一天就有统一的观感**。旧页面在自己的 Activity 里跑，但外框、背景、顶栏、弹层全部由新宿主渲染——从用户角度看，整个 App 已经是新的了。之后按优先级逐页"升级"为真 Content，升级一个旧壳退一个。

## 3. 视觉语言（现代化的具体规则）

这一章是"现代化"落地成可换的参数。所有这些都归**界面包**（第 4.2 节）管，主题包不碰。

### 3.1 形状族（Shape Family）—— 现代化的第一抓手

旧体系只有"圆角大小"一个维度（4 档 + 一个缩放系数），做不出风格。**新体系引入形状族**：一个族定义一组容器的"性格"，全 App 统一。

| 族 | 观感 | 适合 |
|---|---|---|
| **Soft 柔和** | 连续圆角（苹果/M3 风格），圆角随尺寸自适应 | 默认，耐看 |
| **Round 圆润** | 大圆角，按钮直接胶囊，活泼亲和 | 轻松阅读 |
| **Sharp 利落** | 小圆角，边缘干净，信息密度高 | 效率优先 |
| **Petal 花瓣** | 不对称圆角（M3 Expressive 风格），有设计感 | 个性化、年轻 |
| **Cut 切角** | 斜切角，硬朗 | 极客风 |

每个族 = 一组定义：容器圆角曲线 / 按钮形状 / 输入框形状 / 标签形状 / 图标容器形状。
再叠一个 **缩放系数**（0 = 全方，1 = 基准，1.5 = 超圆）——族定性格，系数定强弱。

### 3.2 玻璃材质（Glass）

不是"调个透明度"，是一套四件套，界面包给出四值：

| 组成 | 参数 | 作用 |
|---|---|---|
| **背景模糊** | blur 0~30dp | 把身后的内容糊开，这是"玻璃感"的来源 |
| **基底透明度** | alpha 0~1 | 玻璃本身透多少 |
| **高光描边** | stroke 开关 + 亮度 | 顶边一条亮线，模拟玻璃边缘反光 |
| **噪声纹理** | noise 0~1 | 极细颗粒，消除色带、让材质"有实体感" |
| **饱和度提升** | vibrancy 0~1 | 透出的颜色更鲜艳一点（iOS 式 vibrancy） |

关掉玻璃（界面包设 `glass.enabled = false`）时：容器退回**实色 + 细描边**，依然好看——这是给低端机和"不喜欢玻璃"用户的兜底。

### 3.3 动效（Motion）

动效是"现代化"最容易被感知的部分，也是旧版最缺的。

| 动效 | 用在哪 | 说明 |
|---|---|---|
| **容器变换** Container Transform | 列表项 → 详情页 | 封面/卡片平滑展开成新页面，不是硬切 |
| **共享元素** | 封面、头像跨页 | 同一个元素在两个页面间连续移动 |
| **弹性曲线** Spring / Overshoot | 所有过渡 | 应用"果冻感"曲线，不是线性 |
| **图标形变** | 底栏/侧栏选中 | 选中时图标做形变 + 微弹（M3 Expressive 风格） |
| **顶栏折叠** | 滚动时 | 大标题收成小标题，顶栏材质从 E0 升到 E2 |
| **底栏响应** | 滚动时 | 向下滚隐藏、向上滚出现（可选常驻） |
| **骨架微光** Shimmer | 加载中 | 占位块上流动的高光 |
| **按压反馈** | 所有可点元素 | 涟漪 + 轻微缩放 |

界面包给**动效强度**三档（克制 / 标准 / 生动）+ 一个"减少动效"开关（无障碍，尊重系统设置）。

### 3.4 排版（Type）

沿用现有 6 级字阶结构，但重新定值（更大、层级更清晰）：

| 级 | 用途 | 特征 |
|---|---|---|
| Display | 页面大标题（顶栏折叠态） | 大、粗、可压缩 |
| Headline | 区块标题 | 中粗 |
| Title | 卡片标题、书名 | 中等偏粗 |
| Body | 正文 | 常规，行高舒适 |
| Label | 按钮、标签 | 中等字重，可全大写 |
| Caption | 辅助信息、时间戳 | 小，弱色 |

新增两件事：
- **字重是参数**：标题字重（常规/中粗/粗）进界面包。
- **中文字间距**：中文标题默认加字距，观感立刻不同（旧版没有）。

### 3.5 间距与密度（Density）

8dp 网格，三档密度联动：

| 档 | 系数 | 屏幕边距 | 卡片间距 | 列表行高 | 适合 |
|---|---|---|---|---|---|
| 紧凑 | 0.85 | 12dp | 6dp | 48dp | 书多、重效率 |
| 标准 | 1.00 | 16dp | 12dp | 56dp | 默认 |
| 舒展 | 1.20 | 20dp | 16dp | 64dp | 大屏、重阅读 |

关键改动：**屏幕边距从旧的 12dp 提到 16dp**，区块间距加大——这一条单独就能让观感"呼吸"起来。

### 3.6 图标（Icon）

| 项 | 说明 |
|---|---|
| **统一线宽** | 界面包给基准线宽，全 App 几百个图标显示层统一缩放（不改图标文件） |
| **风格切换** | 描边 / 填充两种，界面包选 |
| **选中动效** | 底栏/侧栏选中时图标形变 + 微弹 |
| **容器形状** | 图标按钮的底盘形状跟随形状族 |

### 3.7 色彩语义（Color）

沿用已建成的种子色引擎（38 个角色 + 4 种夜间策略），新增：

- **强调色块**：大面积使用 primary/secondary 容器色做区块背景（Expressive 风格），敢于用色
- **语义色分层**：背景 → 表面 → 表面变体 → 容器 → 内容，五层清晰
- **对比度自校**：种子色推出后自动检查正文对比度，不达标自动微调

### 3.8 状态（State）

每个页面都要有这四种状态，全部由组件库统一提供：

| 状态 | 表现 |
|---|---|
| 加载 | **骨架屏** shimmer，形状和内容布局一致（不是转圈） |
| 空 | 插画 + 一句人话 + 一个行动按钮 |
| 错误 | 图标 + 一句人话 + 重试按钮 |
| 成功/完成 | 微动效确认（对勾形变、轻微震动） |

### 3.9 现代化清单自检

做完后逐条对照第 1.2 节的 10 条目标。任何一条没达到，视为该期未完成。

## 4. 包体系（沿用你的原则，扩展维度）

**归口判据不变**：换美术包要不要动几何？要动几何的（形状、间距、动效、线宽）归界面包；只有"换了不影响任何尺寸"的（颜色、字体、图片）才归主题包。

### 4.1 主题包（美术素材）

一个 zip，**只装美术**：

```json
{
  "formatVersion": 2,
  "id": "hazel",
```

### 4.2 界面包（非美术参数）

一份 json，**只装结构**：

```json
{
  "formatVersion": 2,
  "id": "float-glass",
  "name": "悬浮玻璃",
  "nav":     { "position": "float", "visibility": "autoHide", "labelMode": "auto" },
  "shape":   { "family": "round",  "scale": 1.2 },
  "glass":   { "enabled": true, "alpha": 0.42, "blur": 20, "stroke": true, "noise": 0.05, "vibrancy": 0.3 },
  "density": { "level": "standard" },
  "motion":  { "level": "expressive", "reduce": false },
  "icon":    { "style": "outlined", "stroke": 1.8, "selectedMorph": true },
  "type":    { "titleWeight": "bold", "cjkSpacing": true },
  "bar":     { "topElevation": "E2", "bottomElevation": "E3", "collapse": true }
}
```

| 旋钮 | 参数 | 现代化贡献（对应 1.2 目标） |
|---|---|---|
| **导航** | 位置（底栏/悬浮/侧栏/顶栏）、可见性、标签显示 | 目标 10 |
| **形状族** | 族（soft/round/sharp/petal/cut）+ 缩放系数 | 目标 1 |
| **玻璃** | 开关 + 模糊/透明/描边/噪声/饱和度五值 | 目标 2、3 |
| **密度** | 三档 + 自由微调 | 目标 5 |
| **动效** | 强度三档 + 减少动效开关 | 目标 4 |
| **图标** | 风格、线宽、选中形变 | 目标 8 |
| **排版** | 标题字重、中文字距 | 目标 6 |
| **栏材质** | 顶栏/底栏各用哪一档材质、是否折叠 | 目标 7 |

**铁律**：界面包里**没有任何按页面分的字段**。所有窗口读同一组值——这是"全局统一"的机制保证（验收第 5 条）。

### 4.3 包库与包内编辑（沿用已确认的模型）

```text
我的 → UI 设置 → 主题和界面管理中心
                    ├─ 主题选包（包库）
                    │    ├─ 官方主题（晴空白 / 墨夜黑 / AMOLED / 纸张米 / 动态取色 / 电子墨水）
                    │    └─ 我的主题包 1 / 2 / 3 / …（新建 / 导入 / 克隆 / 删除，数量不限）
                    │         └─ 包详情：换种子色 / 夜间策略 / 38 色 / 字体 / 背景图 / 纹理
                    └─ 界面选包（包库）
                         ├─ 官方界面包（经典 / 悬浮玻璃 / 侧栏沉浸 / 极简 / 花瓣）
                         └─ 我的界面包 1 / 2 / 3 / …
                              └─ 包详情：换导航 / 形状族 / 玻璃 / 密度 / 动效 / 图标 / 排版
```

- **点包即应用**，换包不重启（Compose 响应式）。
- **包内编辑 = 另存为自定义包**：官方包受保护，编辑时自动克隆为"我的包"。自定义包记录 `basedOn`，可看差异、单项还原、整包删除回基包。
- 自定义包本身就是完整皮肤，可直接导出分享。

### 4.4 内置包清单（首发）

**主题包 6 个**：晴空白（默认）、墨夜黑、AMOLED 纯黑、纸张米、动态取色、电子墨水。
**界面包 5 个**：

| 包 | 导航 | 形状族 | 玻璃 | 动效 | 观感 |
|---|---|---|---|---|---|
| 经典 | 底栏 | soft × 1.0 | 关（实色 + 描边） | 标准 | 干净耐看，接近传统但精致很多 |
| **悬浮玻璃** | 悬浮胶囊 | round × 1.2 | 强 | 生动 | **默认推荐**，最能体现现代化 |
| 侧栏沉浸 | 侧栏 | soft × 1.1 | 中 | 生动 | 大屏/横屏友好 |
| 极简 | 底栏 | sharp × 0.6 | 关 | 克制 | 效率至上 |
| 花瓣 | 悬浮 | petal × 1.3 | 中 | 生动 | 个性、年轻 |

**默认改成"悬浮玻璃"**——这是本轮"视觉现代化"最直观的体现，第一眼就要不同。

## 5. 读书页：冻结 + 预留接口

### 5.1 冻结红线（本轮一行不动）

| 红线 | 内容 |
|---|---|
| 阅读页本体 | `ui/book/read/**`（`ReadBookActivity` 266KB、`BaseReadBookActivity` 及全部子模块） |
| 阅读菜单与配置 | 17 个阅读面板、朗读界面与配置 |
| 视觉资产 | 气泡包（AdvancedTip，含 SVG/Data URL）、高级标题包（AdvancedTitle，含 Lottie）、EPUB 页面模板、纸张纹理 |
| 漫画/视频阅读 | `ReadMangaActivity`、`VideoPlayerActivity` |

冻结 ≠ 丢弃：这些资产的导入 / 导出 / 渲染 / 云备份通道照常可用，本轮任何清理都把它们当黑名单。

### 5.2 预留接口（以后接进来时不返工）

现在就定义好桥接口，读书页本轮**默认不调用**，等 B 系列（读书界面工程）开工时决定开关：

```text
ReaderBridge（读书页 ↔ 新主题体系 的唯一通道）
├─ 可取：部分语义色（背景/正文/强调/分隔）、界面字体、背景图、纹理
├─ 可选：全部跟随 / 只跟字体和背景 / 完全自治（现状，默认）
└─ 不可取：形状、玻璃、动效、密度（这些动了会影响排版与翻页性能）
```

接口设计原则：
1. **读书页主动来问，主题体系不主动灌**——本轮读书页不调用即等于冻结。
2. 取值接口返回的是"名字 → 值"，读书页自己决定怎么用，不被迫改渲染方式。
3. 未来的 B 系列只需在设置里加一个"读书界面跟随主题"开关，打开即接线，不需要改方案、不需要改骨架。

### 5.3 边界处的规则

阅读页**打开的弹窗、确认框、分享面板**这些"非阅读配置"的界面，归新体系管（沿用 V4 接缝规则，仍然有效）。

## 6. 旧代码处置（不保留存档，该扔就扔）

前提 5 决定了这一章的写法：**不做迁移器、不做双写、不做兼容层**。旧设置在新版里就是"没有"，最后一期给一个"从旧版本导入"的一次性转换器。

### 6.1 保留并复用的底座（质量高、有单测）

| 资产 | 位置 | 为什么留 |
|---|---|---|
| 种子色引擎 | `modules/theme/.../palette/SeedPalette.kt`（38 角色 / 4 策略 / 对比度计算） | 纯 Kotlin、无 Android 依赖、有单测，是色彩体系的地基 |
| 主题包数据层 | `modules/theme/.../pack/ThemePackageSpec.kt` + `Resolve` | 容错解析已做（半成品包能加载） |
| 界面包数据层 | `modules/uikit/.../layout/LayoutPackageSpec.kt` | 同上 |
| 键名真值表 | `modules/theme/.../apply/ThemeKeys.kt` | 升级兼容性依赖它 |
| 安全解压 | `SafeZipExtractor` / `SafeZipLimits` | 安全规范，直接沿用 |
| 业务逻辑（全部） | `modules/book`、`modules/rhino`、`app/data`、`app/service`、`app/web` | 本轮是 UI 工程，业务不碰 |

**说明**：`Applicator` / `LayoutEngine` 这两个新引擎的**概念**保留（单一取值入口 + 响应式），但**代码重写**——因为要扩维度（形状族、动效、纹理、材质分档）并去掉旧兼容分支。

### 6.2 丢弃（物理删除，不迁移）

| 资产 | 规模 | 处置 |
|---|---|---|
| `MainActivity.kt` | 2141 行 | 由新 Host 取代，职责拆到各组件 |
| `activity_main.xml` | 48 个 View id | 随 MainActivity 删除 |
| `res/xml/pref_config_*.xml` | 12 个 | 设置重写后整体删除（现状只用于搜索索引） |
| `ThemeConfig.kt` / `ThemeApplier` / `ThemeRuntimeKeys` / `AppColorProvider` / `UiKitBridge` | 旧取值栈和兼容壳 | 全部删除，只留 `ThemeKeys` 键名表给导入转换器用 |
| `ThemePackageManager.kt` | 1712 行，与新的 `ThemePackageStore` 双轨并行 | **二选一：留新的**，老的连同 `ThemeConfig.Config` 格式 v2 一起删；云同步在 A4 期按新格式重做 |
| `AppearanceKitManager` / `MainLayoutPresetConfig` / `NavigationBarIconConfig` / `MainBottomNavConfig` | 旧外观/导航配置栈 | 由页面注册表 + 界面包取代 |
| `recreate()` 刷新机制 | 换肤必重启 Activity | 由 Compose 响应式取代，换肤不重启 |
| 双胞胎页面（BookInfo 两套、书架三套、发现两套） | 多套并行 | 只保留一套（选 Compose 化最好的），其余删 |

### 6.3 组件库：从零建

现状 `modules/uikit` 只有 `AppButton` + 状态视图，组件层几乎空白。本轮**从零建全套**，这是"现代化"落地的零件：

| 类 | 组件 |
|---|---|
| 容器 | 卡片、面板、分组、折叠区、表面容器（E0-E3 四档） |
| 列表 | 列表项（单/双/三行）、网格项、可滑动项、分组头、吸顶头 |
| 导航 | 顶栏（大标题折叠）、底栏、侧栏、悬浮胶囊、标签栏、面包屑、返回 |
| 输入 | 文本框、搜索框、开关、滑块、单选/多选、下拉、步进器、颜色选择 |
| 反馈 | 弹窗、底部抽屉、菜单、Toast、Snackbar、进度（线性/环形/不确定）、骨架屏、空态、错误态、确认框 |
| 展示 | 封面图（含占位/骨架/失败）、头像、标签、徽章、角标、分隔线、评分 |
| 图标 | 图标体系（统一线宽 + 描边/填充 + 形变） |

### 6.4 旧设置导入（最后一期做，不是现在）

新版不兼容旧存档（不读旧主题键、不读旧背景图路径、不读旧圆角设置）。最后一期做一个**一次性导入器**：

```text
我的 → 设置 → 从旧版本导入
  ① 选一个备份文件 / 或直接读旧版留下的配置
  ② 逐项翻译：
     旧主题色 → 新主题包的种子色
     旧背景图 → 新主题包的 images.background
     旧圆角/透明度 → 新界面包的 shape.scale / glass.alpha
     旧底栏形态 → 新界面包的 nav.position
     旧功能设置 → 新设置项（键名映射表）
  ③ 生成"我的主题包 1" + "我的界面包 1"，可预览、可放弃
```

原则：**导入是"翻译"不是"兼容"**。导入完一次性落在新体系里，之后不再有旧格式的存在。不导入的用户直接全新开始。

| 期 | 名称 | 你看到什么 | 关键产出 |
|---|---|---|---|

| **P3** | 包体系 | 能建包、换包、包内编辑、另存自定义包；切主题包/界面包全 App 秒变不重启 | 双包库 + 管理中心 + 5 界面包 / 6 主题包 |

### 7.1 搬迁顺序（P4 内部）

按"用户多快能碰到"排序，不是按代码难度：

```text
第一批（最高频）  书架 → 主页 → 我的 → 发现
第二批（次高频）  书籍详情 → 搜索 → 阅读记录 → 订阅
第三批（管理中频）书源管理 → 备份恢复 → 书源编辑 → 替换净化
第四批（长尾）    其余管理页，逐个升级；未升级的自动走 LegacyScreenHost
```

每批一个提交、一次可回归，随时可停。

### 7.2 分期原则

- **每期结束都是可用状态**：P1 空壳能装能跑，P2/P3 空壳越来越好看，P4 每批业务回来功能就多一点。
- **读书页全程冻结**：每一期收尾都要做读书界面逐项回归。
- **新特性 minor +0.1**：P1 起每期一个版本号（H.1.20.0 起）。

## 8. 验收标准（上手即验）

### 8.1 骨架（P1）

1. 空壳 App 能安装、能启动、6 个占位 Tab 能切。
2. 四种导航形态（底栏 / 悬浮 / 侧栏 / 顶栏）切换正常，切换后功能入口一个不少。
3. 改形状族 / 玻璃 / 密度 / 动效，全 App 立即变，不重启。
4. **代码里不存在"某个页面自己画外框"的通路**（grep 验收）。

### 8.2 现代化（P2-P3，对照第 1.2 节 10 条）

5. 全 App 任意两个窗口的圆角、形状族、玻璃参数、密度、动效完全一致。
6. 玻璃面板有模糊 + 高光描边 + 噪声，关掉玻璃后变干净实色卡片（两套都好看）。
7. 列表项进详情是容器变换，底栏图标选中会形变。
8. 加载是骨架屏、空态有插画和行动按钮、错误可重试。
9. 换主题包 3 秒内全局变色变字体，不重启；深色模式自动协调、对比度达标。
10. 建 ≥2 个主题包 + ≥2 个界面包，切换/编辑/克隆/删除互不影响。

### 8.3 搬迁（P4）

11. 6 个 Tab 全部搬进新骨架，功能齐全。
12. 未搬迁的旧页面自动套新外框，观感与主页面一致（看不出是两个体系）。
13. 换任意主题包/界面包，已搬迁页和未搬迁页同步变装。

### 8.4 全程

14. 读书界面每次发版逐项回归一致（打开一本本地书对照：字号/背景/翻页/菜单/朗读）。
15. 气泡包 / 高级标题 / EPUB 模板 导入→应用→导出 往返正常。
16. 半成品包（删一半字段）导入正常，缺项回默认；恶意路径/超大 zip 被拒且提示人话。
17. 旧版本设置导入：翻译后主题色/背景图/功能设置基本都在，可预览可放弃。

## 9. 名词小词典

| 词 | 大白话 |
|---|---|
| 骨架 / Host | App 的外框：背景、顶栏、底栏、侧栏、弹层。全 App 只有一套，页面不许自己画 |
| Content | 页面内容。每个页面只写自己那块，外框由宿主给 |
| 页面注册制 | 一张表写明有哪些页面、怎么显示，宿主照表自动生成导航 |
| 三层表面 | L0 背景 / L1 容器 / L2 内容，所有视觉规则都在这个坐标系里 |
| 材质分档 | E0 平铺 / E1 嵌入 / E2 浮起 / E3 悬浮，代替旧的阴影层次 |
| 形状族 | 一套容器的"性格"（柔和/圆润/利落/花瓣/切角），全 App 统一 |
| 真玻璃 | 模糊 + 透明 + 高光描边 + 噪声 + 饱和度，五件套，不是单层半透明 |
| 容器变换 | 列表项平滑展开成新页面的动画，不是硬切 |
| 骨架屏 | 加载时显示和内容布局一致的灰色占位块，带流动高光 |
| 主题包 | 装美术资源的文件：颜色、字体、背景图、纹理 |
| 界面包 | 装结构参数的文件：导航、形状、玻璃、密度、动效、图标、排版 |
| 另存为自定义包 | 改官方包不直接改，自动复制一份成"我的包"再改 |
| LegacyScreenHost | 给还没搬迁的旧页面自动套新外框的容器 |
| 冻结 | 本轮完全不动的代码（读书界面），但留好以后接入的接口 |
